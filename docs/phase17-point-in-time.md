# PHASE 17 — контракт «на момент T»

---

## 1. Правило

Факт допустим для прогноза в момент T только если

```
effective_at <= T  И  observed_at <= T
```

Первое условие — факт действовал. Второе — мы о нём знали. Смешивать их
нельзя: состав, выгруженный сегодня, действовал и месяц назад, но
известен тогда не был.

Модель времени введена в Phase 16 (`src/sources/base.Provenance`,
`src/sources/temporal.TemporalRosterStore`). Phase 17 добавляет
недостающее звено — **признаки на произвольный момент T**.

---

## 2. Почему понадобился отдельный движок

Замороженные модули считают признаки walk-forward, но **на момент старта
матча**. Настоящий прогноз делается раньше, и за это время команды
успевают сыграть.

Замер по 109 754 матчам — хотя бы одна из двух команд играет:

| Окно до старта | Доля матчей |
|---|---:|
| 1 час | **32.3%** |
| 3 часа | 64.7% |
| **24 часа** | **85.0%** |
| 7 суток | 96.7% |

То есть признаки на T−24ч отличаются от признаков на старте у
**большинства** матчей. **Гипотеза P2 подтверждена.**

---

## 3. Как реализовано

Один проход по слитой временной шкале двух видов событий:

```
PREDICT(match_i) в момент  T_i = start_i − horizon
UPDATE(match_j)  в момент  start_j
```

События сортируются по времени. При `PREDICT` состояние только читается,
при `UPDATE` — только меняется. При равном времени `PREDICT` идёт
**раньше** `UPDATE`: матч, стартующий ровно в момент прогноза, исхода к
этому моменту ещё не имеет.

Тонкость, ради которой всё и затевалось: матч j может начаться **позже**
T_i, но **раньше** start_i. В обычном walk-forward он попал бы в признаки
матча i; здесь — нет.

Проверка: `test_match_between_prediction_time_and_start_is_invisible`
с обратным контролем (при горизонте 0 тот же матч обязан влиять).

---

## 4. Верность замороженным формулам

При `horizon = 0` движок обязан воспроизвести замороженный конвейер.
Результат сверки на 109 754 матчах:

| Признак | max\|Δ\| |
|---|---:|
| `elo_difference` | 5.7e-14 |
| `form_3_difference` | 8.3e-17 |
| `elo_mean_diff` | 1.4e-12 |
| `five_vs_team_elo_diff` | 1.4e-12 |

Машинная точность. Формулы скопированы из `src/ratings/engine.py`,
`multi_window_features.py`, `player_features.py`,
`roster_representation.py` буква в букву.

`hero_exp_decay_diff` **не пересчитывается**: собственная реализация
расходилась максимум на 0.0018, и подменять ею замороженный признак
значило бы незаметно менять baseline. В экспериментах он берётся из
кэша замороженного конвейера, а в режиме PRE_DRAFT не используется вовсе.

---

## 5. Дефект, найденный при сверке

Первая версия загрузчика брала **одно** множество матчей и для
обновления состояния, и для выдачи признаков. Замороженный конвейер так
не делает: Elo и форма обновляются по **всем** pro-матчам, а признаки
выдаются только для подмножества с полным драфтом и десятью игроками.

Расхождение team-Elo: **в среднем 2.1, максимум 48.3**. Формула была
верной, популяция — нет.

Дефект не виден без сверки с эталоном: числа выглядели правдоподобно.
После разделения популяций (`emit_only`) расхождение упало до 5.7e-14.
Тест `test_emit_only_restricts_output_not_state_updates` фиксирует
разделение.
