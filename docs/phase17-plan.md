# PHASE 17 — план

> Цель: впервые получить честный ответ на вопрос **«насколько хорошо
> модель предсказывает реальные будущие матчи, используя только то, что
> действительно было доступно до матча?»**
>
> Baseline на входе: **225/225 тестов**, frozen model Phase 9,
> калибровка Phase 14.

---

## 1. Что заморожено и не трогается

```
модель:      LogisticRegression, 5 признаков, K=16, form=3, seed=42
калибровка:  beta, скользящее окно 5000 (phase14-beta-rolling5000-v1)
```

Модели уровней доступности (T1, T2) — **отдельные** объекты со своими
версиями. Замороженная модель остаётся эталоном сравнения.

---

## 2. Гипотезы, зафиксированные до экспериментов

| # | Гипотеза | Предсказание | Опровергается, если |
|---|---|---|---|
| **P1** | Не все замороженные признаки доступны до драфта | `hero_exp_decay_diff` требует пиков | все пять вычислимы pre-match |
| **P2** | Горизонт прогноза меняет признаки | признаки на T−24ч ≠ на старте у большой доли матчей | доля мала |
| **P3** | Потеря драфта стоит меньше, чем потеря состава | Δacc(T0→T1) < Δacc(T1→T2) | наоборот |
| **P4** | Переход на модель без состава лучше подстановки нулей | log loss ниже при переходе | не хуже подстановки |
| **H-META** | Сила пула героев команды в текущей мете даёт сигнал | Δlog loss > 1e-4 на VALIDATION | Δlog loss ≤ 1e-4 |

Критерий отбора объявлен заранее и после экспериментов **не менялся**.

---

## 3. Протокол

* всё выбирается на VALIDATION;
* TEST — **одно** обращение после фиксации конфигурации;
* каждое сравнение — на одном и том же наборе матчей;
* block bootstrap с временными блоками (блок=20, n=2000) и McNemar для
  парной accuracy;
* negative control (признак из шума) в каждой матрице.
