Дата исследования: 2026-08-24.
Статус: часть фактов подтверждена напрямую (код/схемы/API-спецификации), часть — через веб-поиск (снэпшоты страниц, не прямой запрос к API из-за сетевых ограничений среды — см. `environment-constraints.md`). Уровень достоверности указан для каждого источника явно.

## Как проверялось

- **[verified]** — подтверждено чтением исходного кода/спецификации/схемы БД проекта [odota/core](https://github.com/odota/core) (склонирован в `/home/user/odota/core` для исследования) или реального JSON-примера ответа API, включённого в тот репозиторий.
- **[web]** — подтверждено через веб-поиск (актуальные страницы документации/статьи), но не прямым HTTP-запросом к самому API (см. ограничения среды).
- **[unverified]** — упоминается в задании, но не подтверждено ни одним из способов; помечено отдельно.

## Ключевые проверенные факты об OpenDota (из чтения исходного кода `odota/core`)

1. **Эндпоинты, относящиеся к матчу**: `/matches/{match_id}`, `/proMatches`, `/publicMatches`, `/teams`, `/teams/{team_id}`, `/teams/{team_id}/matches`, `/teams/{team_id}/players`, `/teams/{team_id}/heroes`, `/leagues`, `/leagues/{league_id}`, `/leagues/{league_id}/matches`, `/players/{account_id}/...`, `/heroStats`, `/explorer` (произвольный SQL к их read-реплике Postgres).
2. **Драфт хранится и отдаётся** в виде массива объектов `{is_pick: bool, hero_id: int, team: 0|1, order: int}` — подтверждено реальным примером ответа Valve GetMatchDetails, который использует OpenDota.
3. **OpenDota уже фильтрует "профессиональные" матчи** по признаку `leagues.tier IN ('premium', 'professional')` — это прямо видно в коде вставки матчей (`svc/util/insert.ts`). Это готовый, проверенный фильтр качества, который стоит унаследовать (и дополнительно сверять с datdota).
4. **OpenDota уже считает собственный Elo-рейтинг команд** (таблица `team_rating`): классическая формула Elo, K=32, базовый рейтинг 1000, обновление после каждого матча. Это даёт нам верифицированный baseline-алгоритм "из коробки" — но для leakage-safe тренировки нам всё равно нужно **пересчитывать Elo самим**, идя по матчам в хронологическом порядке, т.к. API отдаёт только текущий срез рейтинга, а не его историю на момент каждого матча.
5. **Схема таблицы `matches`** содержит помимo базовых полей ещё `radiant_gold_adv`/`radiant_xp_adv` (временные ряды), `teamfights`, `objectives`, `draft_timings`, `picks_bans` — это то, что панятно доступно только **после** матча (не для pre-match prediction, но полезно для построения признаков "сила игры на драфте", post-hoc анализа и, в будущем, live/in-game prediction).
6. **Патчи**: `odota/dotaconstants` содержит таблицу патчей с точными временными метками начала действия (61 запись от 6.70 до 7.41), что даёт надёжный способ проставить `patch` любому матчу по `start_time` без обращения к стороннему API.

## Источники, упомянутые в задании, но не давшие проверяемых новых сведений

- **Официальные источники Valve вне Steam Web API** (например, официальный DPC-сайт) — не проверялись отдельно, т.к. Steam Web API и League endpoints уже покрывают потребность в match/tournament id.
- **GosuGamers / Esports Charts** — рассматривались, но не являются источником telemetry-данных о матчах; полезны разве что как вторичный сигнал "важность турнира" (зрительские метрики), не приоритет для MVP.
