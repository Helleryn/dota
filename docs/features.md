# PHASE 3 — Feature Catalog

Для каждого признака фиксируется: определение, источник, формула, момент доступности
(available at), тип данных, стратегия обработки пропусков, риск утечки данных и
ожидаемая предсказательная ценность (гипотеза, подлежащая проверке в Phase 7/8).

Обозначение `t` = момент начала матча, для которого строится прогноз (`start_time`
предсказываемого матча). Любой признак обязан использовать только данные с
timestamp < `t`. Подробный аудит — в `docs/data-leakage.md`.

## H. Draft

### H.1 Pre-draft (доступно ДО начала драфта — это то, что использует MVP)

На этом этапе из "драфтовых" данных доступно ровно ничего специфичного для конкретного матча — только *агрегированная предыстория* команды в драфте в целом (не привязанная к героям именно этого матча):

| Feature | Definition | Calculation | Available at | Leakage risk |
|---|---|---|---|---|
| `team_hero_pool_size` | (дублирует признак из категории D — общая "гибкость" драфта команды) | См. категорию D | До `t`, до драфта | Низкий |
| `team_first_pick_rate` | Как часто команда исторически имеет первый пик (если известно из истории турнирного посева/coin toss) | Агрегат по прошлым матчам | До `t` | Низкий, но слабо предсказуемо для будущего матча (кто получит first pick, часто решается coin toss/результатом предыдущей игры серии) |

### H.2 Draft-aware (доступно ТОЛЬКО ПОСЛЕ завершения драфта, до начала первого убийства/начала игры)

Это отдельный режим прогноза, архитектурно предусмотренный, но **не входящий в MVP**:

| Feature | Definition | Calculation | Available at | Leakage risk |
|---|---|---|---|---|
| `picks_avg_patch_winrate` | Средний win rate 5 выбранных героев на текущем патче (по всей про-сцене) | `mean(hero_winrate_on_patch(hero_id))` по пикам команды | После завершения драфта, до начала игры | **Высокий, если применить к pre-match режиму** — это по определению недоступно до драфта; должно жёстко физически отсутствовать в pre-draft датасете |
| `bans_denied_strength` | Насколько сильных (по текущему патчу) героев забанила команда у оппонента | `mean(hero_winrate_on_patch(banned_hero_id))` по банам, адресованным оппоненту | После завершения драфта | Тот же риск |
| `draft_order_advantage` | Позиционное преимущество очерёдности пиков/банов (last pick advantage и т.п.) | Из `order` в `picks_bans` | После завершения драфта | Тот же риск |
| `matchup_advantage_score` | Суммарное преимущество состава по матрице герой-контрит-герой | Матрица `matchups` (OpenDota `/heroes/{id}/matchups`) применённая к 5v5 составам | После завершения драфта | Тот же риск |
| `team_hero_comfort` | Насколько выбранные герои — "коронные" для конкретных игроков состава | Per-player hero winrate/games на выбранном герое | После завершения драфта | Тот же риск (плюс зависит от Feature Set 2, player-level данных) |

Архитектурное решение: pre-draft и draft-aware — это **два разных набора признаков одной и той же модели или две модели**, точное решение — предмет Phase 4 (architecture) и Phase 10 (API). Здесь фиксируется только то, что они принципиально не должны смешиваться в одном pre-match датасете.

## Feature Sets — поэтапное добавление (для Phase 7)

Цель разбиения — эмпирически проверить, что каждый следующий блок действительно улучшает метрики (log loss / Brier / ROC-AUC), а не добавлен "потому что кажется логичным".

| Feature Set | Состав | Источник(и) | Гипотеза для проверки |
|---|---|---|---|
| **Set 0 — Baseline** | `team_elo`, `recent_winrate_10` | OpenDota (только матчи) | Даёт ли вообще Elo+форма прирост над "always predict higher Elo team" |
| **Set 1** | + `team_winrate_on_current_patch`, `team_matches_on_current_patch`, `league_tier`, `bo_type`, `h2h_winrate_alltime` (с gating по `h2h_matches_count`) | OpenDota + `dotaconstants` | Дают ли patch-контекст и турнирный контекст прирост сверх голого Elo |
| **Set 2** | + `roster_matches_played`, `days_since_roster_change`, `recent_roster_change_flag`, `team_avg_career_matches` | OpenDota (реконструкция ростера) + опционально Liquipedia | Подтверждается ли гипотеза задания "смена состава обесценивает старую статистику" |
| **Set 3** | + `bracket_stage`, `is_elimination_match`, `team_avg_recent_individual_form`, `team_hero_pool_size` | Liquipedia + OpenDota player_matches | Даёт ли турнирный bracket-контекст и индивидуальная форма дополнительный прирост |
| **Set 4 — Draft-aware** | + весь блок H.2 (`picks_avg_patch_winrate`, `bans_denied_strength`, `draft_order_advantage`, `matchup_advantage_score`) | OpenDota `picks_bans` + `/heroStats`/`/matchups` | Насколько сильно прогноз "до драфта" отличается от прогноза "после драфта" — ключевая метрика для Phase 12 (before/after draft delta, см. задание раздел 12) |

Каждый Feature Set — отдельный прогон backtesting (Phase 8) с фиксацией метрик. Набор считается оправданным, только если он статистически значимо улучшает log loss/Brier относительно предыдущего набора на held-out периоде (см. `docs/research-summary.md`, п. 12).
