# ADR-001: Основной источник данных — OpenDota

## Статус
Принято (2026-08-24, Phase 1-2)

## Context

Для построения датасета профессиональных матчей Dota 2 нужен основной источник
match-level телеметрии (результат, длительность, состав, драфт). Рассмотренные
варианты: OpenDota, STRATZ, Steam Web API напрямую, Dotabuff, datdota — полное
сравнение в `docs/data-sources.md`.

## Decision

Основной источник для MVP (V1) — **OpenDota REST API**. Дополняющий (не
альтернативный) источник для организационных данных, которых нет в OpenDota
структурированно (roster history, bracket/stage) — **Liquipedia**, начиная с
V2/V3. **STRATZ** — зарезервирован как fallback-адаптер на случай
недоступности OpenDota, не задействован в V1.

## Alternatives

1. **Steam Web API напрямую** (первоисточник) — отклонено для V1: не даёт
   готового способа отфильтровать "профессиональные" матчи (нет built-in
   tier-классификации лиг), требует самостоятельно строить то, что OpenDota
   уже построил и поддерживает.
2. **STRATZ как основной** — отклонено для V1: сопоставимые данные, но GraphQL
   вместо REST (выше порог входа для первой итерации), а advanced-тиры API
   требуют реферальных квот, неприменимых к исследовательскому проекту.
   Остаётся как fallback-адаптер (см. `docs/architecture.md`, Source
   Abstraction).
3. **Dotabuff scraping** — отклонено полностью: нет официального API, нет
   опубликованных условий на автоматизированный доступ, юридический риск без
   компенсирующей выгоды (те же данные легально доступны через OpenDota).
4. **datdota как основной** — отклонено: не подтверждён публичный API-контракт
   (`REQUIRES LIVE VERIFICATION`, см. `docs/data-sources.md`). Используется
   только как ручной QA-инструмент для сверки качества фильтрации
   про-матчей.

## Why

- Официально документированный REST API (`VERIFIED` чтением исходников
  `odota/core`), бесплатный без ключа.
- Эндпоинт `/explorer` (произвольный SQL) резко упрощает построение
  агрегатов и оценку исторического покрытия.
- Уже фильтрует про-матчи по `leagues.tier IN ('premium', 'professional')` —
  готовый quality-фильтр, не нужно строить с нуля.
- Отдаёт структуру драфта (`picks_bans`) и посекундные player-level данные —
  покрывает потребности не только V1, но и V2-V4 без смены источника.
- Open source (MIT) — при необходимости можно инспектировать логику
  агрегации и даже развернуть собственный инстанс в крайнем случае.

## Consequences

- Архитектура обязана изолировать OpenDota-специфичную логику за интерфейсом
  `DataSource` (см. ADR ниже и `src/datasources/base.py`), чтобы переход на
  STRATZ/другой источник не требовал переписывания feature engineering и ML.
- MVP наследует ограничения OpenDota: roster — это all-time агрегат, не
  point-in-time (требует собственной реконструкции, см.
  `docs/team-identity.md`); bracket/stage отсутствует (требует Liquipedia
  в V2+).
- Проект зависит от некоммерческого волонтёрского сервиса — нет SLA. Смягчается
  через Source Abstraction (быстрый переход на fallback) и через хранение
  Raw Data (см. ADR-002) — при потере доступа к OpenDota уже собранные данные
  не теряются.
