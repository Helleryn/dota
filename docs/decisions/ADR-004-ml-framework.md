# ADR-004: ML-стек — scikit-learn + CatBoost, pandas, единый интерфейс модели

## Статус
Принято (2026-08-24, Phase 4)

## Context

Задание требует сравнить baseline-модели (random, "сильнее по Elo", логрег,
Random Forest, CatBoost/LightGBM/XGBoost) и явно предупреждает не усложнять
без доказанной пользы (раздел 31 исходного задания: "если сложная модель даёт
+0.2% ценой 10x сложности — не нужна"). Также нужно выбрать библиотеку
обработки данных (pandas vs Polars).

## Decision

- **Data processing:** `pandas` для MVP.
- **Baseline модели:** `scikit-learn` (`LogisticRegression`, `RandomForestClassifier`)
  как обязательные baseline, обёрнутые в единый интерфейс `BasePredictionModel`
  (см. `docs/ml-architecture.md`).
- **Основной gradient boosting кандидат:** `CatBoost`. `LightGBM`/`XGBoost` —
  документированные альтернативы для эмпирического сравнения в Phase 8, но не
  реализуются первыми.
- **Калибровка:** `sklearn.calibration` (Platt scaling / isotonic regression) —
  не отдельная библиотека.
- **Объяснимость:** `SHAP` — единственная выделенная зависимость сверх
  указанных, т.к. нужна для both CatBoost и sklearn-моделей одним API.

## Alternatives

1. **Polars вместо pandas** — отложено, не отклонено навсегда. На объёме
   MVP-датасета (про-матчи, не миллионы строк public matches) разница в
   производительности не критична, а экосистема (scikit-learn, CatBoost,
   SHAP) ожидает pandas/numpy "из коробки" — Polars потребовал бы
   конвертации на границах и так. Пересмотреть, если/когда датасет
   расширится до public matches (V5+, вне текущего скоупа).
2. **LightGBM или XGBoost как основной вместо CatBoost** — не отклонено, а
   отложено до Phase 8 сравнения. Предварительное обоснование выбора
   CatBoost первым кандидатом: нативная поддержка категориальных признаков
   (`patch`, `league_tier`, `bo_type` — как раз то, чем богат наш feature
   catalog, см. `docs/features.md`) без ручного encoding, ordered boosting
   снижает риск переобучения на умеренных по объёму датасетах (наш случай —
   не Kaggle-scale миллионы строк), меньше чувствительность к
   гиперпараметрам "из коробки". Это гипотеза, а не вывод — Phase 8 обязан
   её проверить эмпирически против LightGBM/XGBoost, а не принять на веру.
3. **Нейросеть (PyTorch/TensorFlow) в MVP** — отклонено явно по требованию
   задания: "если CatBoost + хорошие признаки дают 67%, а нейросеть — 67.2%
   ценой 10x сложности — выбираем CatBoost". Табличные данные умеренного
   объёма — типичная зона, где градиентный бустинг превосходит или
   сопоставим с нейросетями при кратно меньшей сложности инфраструктуры.
   Не исключается на будущее (V5, live/in-game prediction с
   последовательными данными — там нейросеть может быть оправдана
   архитектурно, например RNN/Transformer по game state), но не для
   pre-match табличной модели.
4. **AutoML-фреймворк (H2O, AutoGluon)** — отклонено: непрозрачность
   решения противоречит явному требованию объяснимости прогноза
   (раздел "Main factors" в задании), а также добавляет тяжёлую
   зависимость ради задачи, которая решается 4-5 явно сравниваемыми
   моделями.

## Why

Явное требование задания: "максимальная реальная predictive performance при
разумной сложности и надёжности" — не технологии ради технологий. Единый
интерфейс `BasePredictionModel` (см. `docs/ml-architecture.md`) делает выбор
конкретного алгоритма низкорисковым решением — его можно поменять по
результатам Phase 8 без переписывания dataset builder, backtesting engine
или API.

## Consequences

- Любая модель обязана реализовывать `predict_proba` (не только `predict`) —
  задание требует вероятности, не только класс-победитель.
- `MLflow` и подобные experiment-tracking системы **не подключаются в MVP**
  (см. `docs/ml-architecture.md`, раздел Model Registry) — их отсутствие не
  должно заблокировать подключение позже: `models` таблица в БД уже
  спроектирована с полями, совместимыми по смыслу с MLflow run metadata
  (`config`, `metrics` как JSONB).
- CatBoost как первый кандидат означает первую же ML-зависимость проекта
  сверх scikit-learn — фиксируется в `requirements.txt`/`pyproject.toml`
  явно, с версией.
