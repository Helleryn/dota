## Обнаруженный факт

Эта сессия Claude Code работает в изолированном контейнере с политикой сетевого egress, разрешающей исходящий HTTPS **только** на ограниченный список хостов:
`github.com`, `*.githubusercontent.com`, `registry.npmjs.org`, `pypi.org`, `files.pythonhosted.org`, `jsr.io`, `proxy.golang.org`, `api.anthropic.com` и ряд служебных/внутренних адресов.

Это **организационная политика egress-прокси** этой конкретной среды выполнения (см. `/root/.ccr/README.md`): "The destination host is not allowed by your organization's egress policy for this session. Do not retry or route around it." Обходить её нельзя и не нужно — это осознанное ограничение, а не баг.

## Что это значит для проекта

1. **Исследование источников данных (Phase 1) было проведено не "вслепую"**: реальные факты об OpenDota API (эндпоинты, лимиты, схема БД, структура picks_bans) подтверждены не HTTP-запросом к живому API, а чтением **исходного кода** проекта `odota/core` (склонирован через `github.com`, который в allowlist) — это даже надёжнее, чем один живой запрос, так как видна вся логика, включая rate-limit конфиг по умолчанию и формулу Elo.
2. **В этой конкретной среде нельзя прямо сейчас запустить реальный сбор данных** (fetch matches с OpenDota/STRATZ/Steam API) — все нужные хосты заблокированы политикой.
3. Это не блокирует Phase 1–4 (исследование, feasibility, feature catalog, архитектура, схема БД) — их можно и нужно продолжать.
4. Это **блокирует Phase 5 (ingestion pipeline с реальными данными)** в текущей среде "как есть".

## Варианты продолжения (нужно решение пользователя)

1. **Написать ingestion-код здесь, запускать сбор данных вне этой среды.** Я пишу полноценный, протестированный на моках/фикстурах data collector (клиент OpenDota API, rate limiter, retry-логика, валидация), плюс unit-тесты на сохранённых JSON-фикстурах (аналогичных найденным в `odota/core/json/*`). Реальный прогон сбора данных пользователь запускает сам — локально или в среде с более широким доступом.
2. **Изменить сетевую политику этой среды.** Если пользователь — администратор окружения на claude.ai/code, он может создать/переключить окружение с другой network policy (allowlist конкретных доменов вроде `api.opendota.com`) — тогда сбор данных можно будет выполнять прямо в этой сессии. Подробнее: https://code.claude.com/docs/en/claude-code-on-the-web.
3. **Использовать локальную копию датасета.** Например, взять готовый Kaggle-датасет (`bwandowando/dota-2-pro-league-matches-2023`) как оффлайн-фикстуру, если пользователь загрузит файл в сессию вручную (через файловую систему), а не через сетевой запрос.

Рекомендация: идти по варианту 1 (писать pipeline здесь, дизайн — production-ready и легко переносимый), и параллельно уточнить у пользователя, доступен ли вариант 2. Ничего не блокирует Phase 2–4.
