# PHASE 18 — расширение домена (гипотеза L4)

**Вердикт: ОТКЛОНЕНА ДО ЭКСПЕРИМЕНТА.** Отрицательный результат.

---

## 1. Гипотеза

> Live shadow Phase 17 дал 38 отказов из 38, потому что домен обучения
> ограничен tier `premium`/`professional`. Если включить лиги tier
> `excluded`, команды из расписания окажутся покрыты, и отказов станет
> меньше.

Гипотеза выглядела естественной и была бы дорогой в реализации:
пересборка домена меняет Elo, форму, player-Elo — то есть всё.

---

## 2. Почему эксперимент не проводился

Перед пересборкой домена был задан вопрос, который её обесценил:
**а есть ли по этим командам данные вообще — при любом tier?**

Измерение:

| Проверка | Результат |
|---|---|
| лиги в расписании Valve DPC | 2, обе tier `excluded` |
| лига 19081 (36 из 41 матча) — матчей в OpenDota | **0** |
| команды этой лиги — матчей в OpenDota при **любом** tier | **0** |
| лиг нашего домена, публикующих будущие матчи | **0 из 15** |

Расширение домена **не чинит** ситуацию: данных по этим командам нет ни
у нас, ни у OpenDota. Расширять домен до множества, которое пусто в
источнике, бессмысленно.

Это тот случай, когда измерение стоило одного запроса, а эксперимент
стоил бы полной пересборки признаков. Порядок «сначала проверить
предпосылку, потом строить» сэкономил фазу.

---

## 3. Что оказалось настоящей причиной отказов

Не домен, а **источник и способ сопоставления**:

| Причина | Phase 17 | Phase 18 |
|---|---|---|
| источник расписания | Valve DPC — только лиги tier `excluded` | bo3.gg, `discipline_id=4` |
| сопоставление | по `team_id` Valve → **0 из 20** команд в базе | по игрокам → **88 из 133** |
| требуемая полнота | полный состав | частичный состав как рабочий режим |

Смена источника и переход к сопоставлению по игрокам дали 9 прогнозов
там, где расширение домена не дало бы ни одного.

---

## 4. Вывод для архитектуры

Отказ live shadow Phase 17 был диагностирован **неверно** — как узость
домена. Правильный диагноз: у Valve DPC и у нашего домена
непересекающиеся множества лиг.

Правило, вынесенное из этого: прежде чем расширять обучающее множество,
проверить, что расширение вообще населено данными.
