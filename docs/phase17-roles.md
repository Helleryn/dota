# PHASE 17 — роли игроков

---

## 1. Три уровня, которые нельзя подменять

```
CONFIRMED_ROLE   заявлено источником на КОНКРЕТНЫЙ матч
ROSTER_ROLE      позиция игрока в составе команды
PREDICTED_ROLE   роль, предсказанная нами
UNKNOWN_ROLE     неизвестно
```

Требование задания — не считать `ROSTER_ROLE` подтверждённой ролью на
матч — выполнено на уровне типов (`src/sources/models.RoleConfidence`),
и повышение уровня нигде в коде не происходит.

---

## 2. Результат исследования доступности

Phase 16 проверила все доступные источники реальными запросами:

| Источник | Роль на конкретный матч | Позиция в составе |
|---|---|---|
| Liquipedia | **нет** | **да**, `position=1..5` с `joindate` |
| bo3.gg | нет | нет |
| Valve DPC | нет | нет (`registered_players` пуст) |
| OpenDota | нет | только `lane_role` — **post-match** |
| STRATZ / PandaScore | не проверено (403) | не проверено |

> **`CONFIRMED_ROLE` не существует ни в одном доступном источнике.**

Позиция из Liquipedia — это роль игрока **в составе**, объявленная при
его приходе, а не назначение на матч. Адаптер размечает её
`PREDICTED_ROLE`; тест `test_liquipedia_role_is_predicted_not_confirmed`
фиксирует, что повысить её нельзя.

---

## 3. Почему это не блокирует фазу

Замороженный набор признаков ролей **не использует**. Phase 11 проверила
player×hero×role и вынесла REMOVE: признаки избыточны с player-Elo.

Отсутствие ролей — ограничение будущих исследований, а не текущего
конвейера. Строить их получение сейчас незачем: подставлять некуда.

`lane_role` из реплея остаётся запрещённым как pre-match факт (Phase 11)
и в Phase 17 нигде не используется.
