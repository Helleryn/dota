## 2. Что дало исследование источников (до гипотез)

### 2.1 Ошибка в Phase 16, которую нашла эта фаза

Phase 16 сообщила: «bo3.gg — 378 предстоящих матчей Dota, медиана запаса
94.8 ч, полный состав у 10.1%».

**Это были матчи Counter-Strike 2.** В bo3.gg `discipline_id=1` — это
Counter-Strike 2, а Dota 2 — `discipline_id=4`. Проверено запросом
`/disciplines`: `[(1,'Counter-Strike 2'), (2,'Valorant'),
(3,'League of Legends'), (4,'Dota 2'), …]`.

Ошибка обнаружилась, когда в матче с tier=s оказались игроки FalleN,
YEKINDAR и yuurih — состав FURIA по CS2.

Настоящие числа для Dota 2:

| Величина | Phase 16 (ошибочно) | Phase 18 (верно) |
|---|---:|---:|
| предстоящих матчей | 378 | **15** |
| медиана запаса | 94.8 ч | **49.3 ч** |
| известны за ≥24 ч | 82.3% | **100%** |
| известны за ≥7 суток | 30.4% | **0%** |
| **полный состав (10 игроков)** | 10.1% | **46.7%** |

Расписание оказалось **вчетверо хуже**, а составы — **вчетверо лучше**,
чем сообщалось. Оба вывода Phase 16 о bo3.gg подлежат замене.

### 2.2 Почему live shadow Phase 17 дал ABSTAIN=38

Установлено измерением, а не предположено:

* обе лиги, публикующие расписание в Valve DPC, имеют tier **`excluded`**;
* лига 19081 (36 из 41 будущих матчей) имеет в OpenDota **0 матчей**;
* все её команды имеют **0 матчей** в OpenDota при **любом** tier;
* **ни одна из 15 лиг нашего домена**, активных за 90 дней, не публикует
  будущих матчей в Valve DPC.

> Расширение домена это **не чинит**: данных по этим командам нет ни у
> нас, ни у OpenDota.

### 2.3 Что реально возможно

bo3.gg даёт 15 предстоящих матчей Dota. Сопоставление **по игрокам**
(не по названию команды) через реестр `proPlayers` OpenDota:

* 133 игрока в предстоящих матчах;
* **88 (66.2%)** сопоставлены однозначно, и **все 88 есть в нашей базе**;
* 17 неоднозначных — корректно не разрешены;
* матчей с полными десятью сопоставленными игроками: **0**; лучший — 9/10.

Значит режим, который надо строить, — **частичный состав**, а не полный.

## 3. Гипотезы (сформулированы до экспериментов)

| # | Гипотеза | Ожидаемое направление | Метрика | Критерий отклонения |
|---|---|---|---|---|
| **L1** | При k<5 известных игроков среднее по известным лучше, чем отказ от признака | log loss ниже, чем у T2 | log loss на VAL | не лучше T2 |
| **L2** | Усадка к базовому уровню при малом k лучше простого среднего | log loss ниже | log loss на VAL | Δ ≤ 1e-4 |
| **L3** | Качество монотонно растёт с числом известных игроков | accuracy(k) не убывает | accuracy по k | немонотонно |
| **L4** | Расширение домена на tier `excluded` увеличивает покрытие команд | больше известных команд | доля покрытых | покрытие не растёт |

Порог отбора — Δlog loss > 1e-4 на VALIDATION, объявлен заранее и после
экспериментов не меняется. В каждой матрице — контроль из шума.

### Гипотезы, отклонённые до эксперимента

| Гипотеза | Почему отклонена сразу |

## 4. Протокол

* всё выбирается на VALIDATION;
* TEST — одно обращение после фиксации;
* сравнения на одном наборе матчей;
* block bootstrap (блок=20, n=2000);
* отрицательные результаты документируются наравне с положительными.

## 5. Риски утечки

| Риск | Как закрыт |
|---|---|
| состав из будущего | `observed_at ≤ T` (Phase 16), PIT-движок (Phase 17) |
| сопоставление игрока по сегодняшнему реестру | **реестр `proPlayers` — снимок «сегодня»**; допустим только для ЖИВОГО прогноза, где T = сейчас, и запрещён для исторического replay |
| частичный состав дополняется | запрещено; известные считаются, число известных сохраняется |
| слияние команд по имени | не выполняется нигде (Phase 10) |

Последний пункт в таблице — новый риск этой фазы, и он ограничивает
применимость сопоставления по игрокам историческим прогнозом.
