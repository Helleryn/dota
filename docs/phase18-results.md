## 3. Pre-match набор признаков по горизонтам

Уровни доступности из Phase 17; Phase 18 меняет только уровень T1.

| Уровень | Что известно | Признаки |
|---|---|---|
| **T0** | всё, включая драфт | 5 признаков Phase 9 — **только post-draft**, для живого прогноза недостижим |
| **T1** | расписание + частичный состав | `elo_difference`, `form_3_difference`, `elo_mean_diff·w(k)`, `five_vs_team_elo_diff·w(k)`, где `w(k)=k/(k+32)` |
| **T2** | расписание без состава | `elo_difference`, `form_3_difference` |

Горизонт на качество T1/T2 практически не влияет (Phase 17): между H0 и
H7сут разница в пределах шума, потому что Elo меняется медленно.
Ограничивает не горизонт, а **полнота состава**.

Реальный живой режим — **T1 с k = 3…4**, не T0 и не T1 с k = 5.

## 5. Adversarial-набор (PART L)

`tests/pit/test_phase18_future_information.py` — 10 тестов, по одному на
каждый способ протечки будущего, плюс сквозной инвариант фазы.

| # | Сценарий | Что проверено |
|---|---|---|
| 1 | будущее объявление состава | `observed_at` отсекает факт, действовавший, но неизвестный |
| 2 | будущий трансфер | прогноз видит старый состав, не новый и не оба |
| 3 | будущая смена роли | роль — новая запись, не мутация старой |
| 4 | будущий патч | два барьера: не вышел / не был известен |
| 5 | статистика героев из будущего | матч между T и стартом не меняет `pool_meta_diff` |
| 6 | результат будущего матча | не меняет ни один из пяти признаков |
| 7 | сопоставление идентичностей задним числом | ключ (источник, id), связь не ретроактивна |
| 7b | конфликт источников | явный `UNKNOWN`, не молчаливый выбор |
| 8 | исправление расписания | старая запись неизменяема, исправление приходит отдельно |
| — | сквозной | неполный состав не дополняется, k виден в признаках |

У каждого теста есть **парный контроль из шума**: при сдвиге T за факт
он обязан стать видимым. Без контроля тест проходил бы и на коде,
который данные игнорирует вовсе.

Две фикстуры при написании оказались вырожденными и были переписаны:

* тест 5 сравнивал `None` с `None` — не передавался провайдер состава;
* сквозной тест сравнивал среднее по двум игрокам со средним по пяти у
  игроков с **одинаковым** рейтингом (player-Elo двигает пятёрку общей
  дельтой), и равенство выполнялось бы на любом коде.

Обе найдены запуском, а не чтением. Это тот же класс ошибки, что в
Phase 17, и он повторился — фикстуру надо проверять на вырожденность
специально.
