# PHASE 20 — сила по позициям (PART B)

**Вердикт: REMOVE.** Δlog loss на VALIDATION **+0.00007** при пороге
**1e-4** — единственный из пяти механизмов, не прошедший даже до
redundancy-аудита.

---

## 1. Механизм и почему он казался перспективным

Phase 9 отвергла **неупорядоченные** меры разброса состава:

| Агрегация | Δaccuracy к базе |
|---|---:|
| `mean` | **+1.79 пп** |
| `std` | +0.33 пп |
| `spread` (max−min) | +0.30 пп |
| `star_power` (max−mean) | +0.30 пп |

Позиционное сопоставление — **другой** механизм. Он спрашивает не
«насколько разбросаны мои игроки», а «мой керри против твоего керри».

Пример из задания: A = 1700/1700/1700/1400/1400 и B = 1600×5 имеют
одинаковое среднее. Против C = 1600×5 позиционные разницы у A и B
различны, а `elo_mean_diff` — нет.

---

## 2. Данные и pre-match доступность

Позиция 1–5 выводится из `lane_role` + ранга GPM внутри пары линии
(`derive_positions`, Phase 11). Покрытие `lane_role` — **98.83 %**.

Статус позиции — **PREDICTED**, и он не повышается:

| Статус | Достижим? | Почему |
|---|---|---|
| CONFIRMED | **нет** | источника роли на конкретный матч не существует (Phase 16/18: `role = None` у всех 133 игроков) |
| **PREDICTED** | да | мода прошлых позиций игрока, 83.5 % walk-forward (Phase 11) |
| UNKNOWN | да | у игрока нет истории |

`lane_role` **текущего** матча — post-match величина и не используется:
тест `test_6_current_match_role_mutation`.

## 3. Дефект, который нашли тесты

Первая версия назначала позиции **всем** игрокам: тем, у кого истории
нет, доставались свободные номера. Тогда `pos_diff_*` считались по
произвольно сопоставленным парам — то есть по выдуманным данным.

Тест `test_7_positions_of_current_match_are_predicted_not_observed`
поймал это: у матча без истории вообще все пять разниц были заполнены.

Исправлено: в сопоставление попадают **только** игроки, чьё назначение
выведено из истории; остальные дают `None`. Одновременно
`pos_assigned_min` стал считать только уверенные назначения, а не все.

Без этой правки признак выглядел бы полным на 100 %, а на деле пятая
часть его значений была бы шумом.

## 4. Результат

| Модель | accuracy | ROC-AUC | log loss | Brier | ECE |
|---|---:|---:|---:|---:|---:|
| M0 | 0.5979 | 0.6425 | 0.6578 | 0.2332 | 0.00884 |
| M0 + H2 | 0.5996 | 0.6422 | 0.6578 | 0.2332 | 0.00847 |

**Δlog loss = +0.00007** — ниже порога 1e-4. ROC-AUC даже **упал**
(0.6425 → 0.6422). Accuracy выросла на +0.0017, но по объявленному
протоколу accuracy не является основанием.

### Redundancy: почему ноль

| Признак | corr с `elo_mean_diff` | corr с исходом |
|---|---:|---:|
| `pos_diff_1` | +0.6769 | +0.1714 |
| `pos_diff_2` | +0.6777 | +0.1689 |
| `pos_diff_3` | +0.6695 | +0.1642 |
| `pos_diff_4` | +0.6809 | +0.1722 |
| `pos_diff_5` | +0.6981 | +0.1704 |
| `pos_bottleneck` | +0.7064 | +0.1733 |
| `pos_best` | +0.7078 | +0.1807 |
| **`pos_imbalance`** | **+0.0019** | **+0.0058** |

Пять позиционных разниц коррелируют с `elo_mean_diff` на 0.67–0.70 —
и это не совпадение, а **тождество, объявленное в плане заранее**:

```
Σ pos_diff_i = 5 · elo_mean_diff
```

Пять слагаемых, сумма которых уже в модели. Независимую информацию может
нести только их *распределение* — и вот оно, в чистом виде:

**`pos_imbalance` коррелирует с исходом на +0.0058.** Практически ноль.

## 5. Ответ на вопрос PART B

> Может ли команда с одинаковым средним player-Elo быть принципиально
> разной по распределению силы по позициям?

**Различаться — может. Предсказывать исход лучше — нет.**

Гипотетический пример из задания (1700×3 + 1400×2 против 1600×5)
реализуем; но `pos_imbalance`, который его ровно и измеряет, не
коррелирует с исходом (+0.0058) и не даёт вклада.

Это **четвёртое независимое подтверждение** одного и того же:

| Фаза | Форма вопроса о структуре состава | Итог |
|---|---|---|
| 7 | стабильность, возраст, непрерывность | ноль |
| 9 | `std`, `spread`, `min`, `max`, `star_power` | все хуже `mean` |
| 11 | player × role | ноль |
| **20** | **сопоставление по позициям** | **ноль** |

Сила пятёрки описывается **средним уровнем игроков** и ничем сверх него.
Phase 9 сформулировала это первой; Phase 20 закрывает последнюю
незакрытую форму вопроса.

## 6. Ограничение результата

Позиция — PREDICTED с точностью 83.5 % (Phase 11). Часть отсутствия
сигнала может объясняться ошибками назначения, а не отсутствием
механизма.

Проверить это можно было бы только при CONFIRMED роли, источника которой
не существует. Поэтому вердикт формулируется точно:

> **REMOVE** для позиционной структуры на PREDICTED роли.
> Для CONFIRMED роли вопрос остаётся **NOT TESTABLE** — не «отвергнут»,
> а неизмерим.
