# PHASE 14 — план: калибровка во времени и онлайн-адаптация

> План зафиксирован **до** экспериментов. Главная цель — **не усложнить
> модель**, а сделать существующий прогноз стабильно калиброванным.

---

## 0. Frozen model — пять входов, и в документации тоже

Задание прямо требует не повторять сокращение до трёх признаков. Модель
Phase 9–13 использует **пять** входов:

```
elo_difference, form_3_difference,                       <- frozen baseline
elo_mean_diff, five_vs_team_elo_diff, hero_exp_decay_diff  <- KEEP Phase 9
```

В коде это константа `PHASE9_FULL` (`scripts/phase13_dataset.py`).
Отдельная константа `PHASE9_ADDITIONS_ONLY` существует только для
воспроизведения сокращённого варианта и **не используется как baseline**.
Фаза 14 базовую модель не трогает: она обучается тем же кодом, на том же
TRAIN, с тем же seed, и остаётся замороженной.

## 1. Протокол

| Правило | Как обеспечивается |
|---|---|
| Все решения — на VALIDATION | метод калибровки, окно, half-life, порядок слоёв |
| TEST — одно обращение | флаг `--final-test`, счётчик в JSON |
| Базовая модель не меняется | переобучается тем же кодом; слой калибровки живёт снаружи |
| Walk-forward, а не пересчёт задним числом | калибратор на момент матча видит только матчи < t |
| Отрицательные результаты не прячутся | вердикт по каждой гипотезе |
| Negative control | калибратор, обученный на перемешанных метках |

## 2. Ключевая опасность фазы

Слой калибровки — **самое удобное место для утечки во всём проекте**.
Наивная реализация («обучить калибровку на всей выборке и применить»)
даёт красивый ECE и полностью бессмысленна: она использует исходы тех
самых матчей, которые калибрует.

Поэтому центральный инвариант — **prefix-only**:

```
для матча t:
    p_raw      = frozen_model(features(t))          # модель заморожена
    p_cal      = calibrator.transform(p_raw, t)     # состояние из матчей < t
    ...наблюдаем исход...
    calibrator.observe(p_raw, y_t, t)               # обновление ПОСЛЕ
```

Тест на это — не опциональная проверка, а условие осмысленности всей фазы.

## 3. Что сравнивается (PART C)

| Модель | Слой калибровки |
|---|---|
| **A** | нет (сырой прогноз) |
| **B** | одна глобальная, обучена на TRAIN, заморожена |
| **C** | скользящее окно последних N матчей |
| **D** | только матчи текущего патча (с запасным вариантом при малой выборке) |
| **E** | экспоненциальное затухание по времени |

Методы (PART M): логистическая (Platt), изотоническая, температурная
(только наклон), бета-калибровка. Сложнее — не рассматривается.

Сетки: N ∈ {500, 1000, 2000, 5000, 10000}; half-life ∈ {7, 14, 30, 60, 90, 180}.

## 4. Гипотезы (до экспериментов)

| # | Гипотеза | Предсказание | Опровергается, если |
|---|---|---|---|
| **H1** | Временной дрейф калибровки реален | скользящий ECE/наклон меняются сверх выборочного шума | колебания внутри доверительных интервалов |
| **H2** | Патч действительно вызывает дрейф | ухудшение калибровки в первые дни сохраняется **после контроля состава выборки** | после перевзвешивания эффект исчезает |
| **H3** | Достаточно рекалибровки без переобучения | вариант «только калибровка» не хуже полного переобучения по log loss / ECE | переобучение заметно лучше |
| **H4** | Онлайн-адаптация улучшает вероятности | ECE и Brier падают при неизменных accuracy и ROC-AUC | ECE не улучшается, либо падает ранжирование |
| **H5** | Сдвиг на андердогах — свойство калибровки, а не данных | смещение снимается монотонным преобразованием вероятности | сохраняется после калибровки ⇒ дело не в отображении |
| **H6** | Вклад hero-сигнала меняется по величине, а не исчезает | коэффициент `hero_exp_decay_diff` падает после патча, знак сохраняется | знак меняется или коэффициент устойчив |
| **H7** | Дрейф калибровки обнаружим заранее | скользящие метрики по прошлым матчам предупреждают об ухудшении | предупреждение не опережает ухудшение |

### Что известно и не проверяется заново
* Информационный потолок (Phase 13: пять семейств в пределах 0.14 пп) —
  принимается как установленный факт, а не проверяется.
* `|p−0.5|` как мера уверенности (Phase 13) — проверяется только то,
  меняет ли калибровка **ранжирование**, а не сама мера.
* Признаки не добавляются: в фазе нет ни одного нового входа модели.

## 5. Контроль смешения (PART B) — центральный методический пункт

Phase 13 обнаружила ухудшение калибровки после патча, но там же нашла,
что первые 30 дней патча отличаются составом матчей (`team_matches_min`
341 против 269, `|elo_difference|` 62.0 против 69.3). Оба различия сами
по себе тянут метрики вниз.

Поэтому в Phase 14 сравнение окон патча проводится **тремя способами**:

1. **сырое** — как в Phase 13, для сопоставимости;
2. **со стратификацией** — внутри децилей `|elo_difference|` и уровня
   лиги;
3. **с перевзвешиванием** — выборка первых дней патча взвешивается так,
   чтобы её состав по (дециль `|elo_difference|` × tier) совпадал с
   составом остального периода.

Эффект признаётся реальным только если он переживает все три.

## 6. Карта утечек (PART S)

| # | Сценарий | Где проверяется |
|---|---|---|
| S1 | калибратор видит исход калибруемого матча | тест prefix-stability слоя |
| S2 | калибровка обучена на будущих матчах | тест «добавление будущего не меняет прошлое» |

| S4 | будущие результаты команд | то же |
| S5 | будущие результаты игроков | то же |
| S6 | будущие остатки калибровки | тест на детектор дрейфа |
| S7 | будущие ошибки модели | тест на детектор дрейфа |
| S8 | будущий состав | ковариаты Phase 13 уже проверены |
| S9 | пост-матчевые метки | усиленный тест: перемешивание будущих меток не меняет прошлых прогнозов |
| S10 | будущие результаты лиг | стратификация считается по прошлому |
