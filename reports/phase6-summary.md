## Как получен многолетний датасет (важная методологическая оговорка)

Phase 5 рекомендовала диапазон 2021-01-01 → сегодня, но живая выборка на
момент начала Phase 6 покрывала только 17 дней (май 2026). Полная
пагинация `/proMatches` до 2021 года физически неосуществима за разумное
время (лимит 60 запросов/мин, ~250к матчей всех tier). Вместо этого
реализован `OpenDotaExplorerSource` (`src/datasources/opendota_explorer.py`)
— bulk-исторический адаптер через `/explorer` (прямой SQL), предусмотренный
ещё в `docs/data-pipeline.md` (Phase 4), но не реализованный до сих пор.
Стратегия: для каждого календарного квартала 2021-Q1 — 2026-Q3 (23
квартала) взяты 120 САМЫХ РАННИХ pro/premium-tier матчей квартала одним
`/explorer`-запросом (`scripts/backfill_historical.py`) — итого 2760 новых
матчей, объединено с существующими 1265 из Phase 5 live (после дедупликации
upsert) в 4025 матчей всего, 2938 pro/premium-tier строк Feature Set 0.

**Ограничение, которое это создаёт (не скрывается)**: непрерывность
`Elo`/`recent_form`/`days_since_last_match` гарантирована ВНУТРИ выборки
каждого квартала (матчи идут подряд с начала квартала), но МЕЖДУ
кварталами есть разрывы — команда, не входящая в первые 120 матчей
следующего квартала, "теряет" часть истории, которую видел бы полный
backfill. Это влияет в первую очередь на `recent_winrate`/
`days_since_last_match` (сильно зависят от полноты недавней истории) и
меньше — на `Elo` (интегрирует историю медленнее, устойчивее к пропускам).
Это прямо связано с находкой ablation ниже (раздел "Ablation").

## Leakage audit

1. **team_a/team_b ≠ winner/loser** (раздел 2): radiant_win rate = 0.5020
   (не тождественно 0/1); корреляция порядка `team_id` с target = 0.5126
   (не тривиальна). Формальный тест: `tests/ml/test_phase6_splits.py`.
2. **Data cutoff audit** (раздел 3-4): независимая (НЕ через RatingEngine,
   через pandas `groupby().cumcount()`) перепроверка `matches_played_before`
   для всех 5876 team-match записей — 0 расхождений. Подтверждает
   `max(source_timestamp) < prediction_timestamp` на реальных данных, не
   только "по построению кода".
3. **Recent form sanity** (раздел 25): для выборочного матча независимо
   пересчитан `recent_winrate` по последним 5 СТРОГО более ранним матчам —
   совпал с сохранённым значением (0.2000 == 0.2000), окно не включает
   текущий матч.
4. **Elo sanity** (раздел 24): mean=1007.48, std=42.02, min=867.78,
   max=1242.73, 0 NaN, 0 inf.
5. **Регрессионный leakage suite**: 49/49 pytest (45 из Phase 5 + 4 новых
   для Phase 6), включая 4 adversarial-теста на реальных данных
   (`scripts/real_data_leakage_audit.py`, не перезапускались в этой фазе —
   не менялся код, на который они нацелены).

**Вывод**: leakage не обнаружена ни одним из 5 независимых методов проверки.

## Baselines и модели (single chronological split, TEST)

| Model | Accuracy | Balanced Acc | Log Loss | Brier | ROC-AUC |
|---|---:|---:|---:|---:|---:|
| Random 50/50 | 0.5057 | 0.5000 | 0.6931 | 0.2500 | 0.5000 |
| Majority (train) | 0.5057 | 0.5000 | 0.6931 | 0.2500 | 0.5000 |
| **Elo only** | **0.5873** | **0.5875** | **0.6711** | **0.2390** | **0.6207** |
| Logistic Regression (raw) | 0.5850 | 0.5842 | 0.6846 | 0.2454 | 0.6087 |
| Logistic Regression (calibrated) | 0.5646 | 0.5654 | 0.8353 | 0.2478 | 0.5968 |
| CatBoost (raw) | 0.5374 | 0.5383 | 0.7030 | 0.2541 | 0.5399 |
| CatBoost (calibrated) | 0.4875 | 0.4929 | 0.6977 | 0.2521 | 0.5357 |

**Честная находка, не приукрашенная**: **Elo-only — лучший результат на
единственном split**, лучше и LogisticRegression (все 3 признака), и
CatBoost. CatBoost не превзошёл ни один более простой baseline — это
результат, а не ошибка эксперимента (см. Walk-forward ниже — та же картина
устойчиво повторяется на 21 периоде, не случайность одного split).

Random и Majority дали идентичные метрики — train-mean (доля побед radiant
в TRAIN) оказался очень близок к 0.5, поэтому Majority-правило выродилось
в почти тот же прогноз, что и чистый random 50/50.

## Calibration (раздел 13)

Isotonic regression, обучена ИСКЛЮЧИТЕЛЬНО на VALIDATION (441 строка),
применена к TEST — TEST не использовался для выбора метода калибровки.

**Находка**: калибровка УХУДШИЛА метрики и для LogReg, и особенно для
CatBoost (log_loss CatBoost: 0.7030 → 0.6977 незначительно лучше, но
accuracy упал 0.5374 → 0.4875, ROC-AUC 0.5399 → 0.5357). Наиболее вероятная
причина — недостаточный объём VALIDATION (441 строка) для устойчивой
isotonic-калибровки: isotonic regression склонна переобучаться на шум
калибровочной выборки при таком объёме (известное свойство метода, не
специфичное для этого проекта). `docs/ml-architecture.md`/ADR-004 прямо
откладывают выбор между Platt/isotonic до Phase 8-9 — здесь зафиксирован
эмпирический аргумент В ПОЛЬЗУ этого решения: на текущем объёме данных
разница между методами калибровки, скорее всего, будет ощутима, и
Phase 6 не должна была решать её "по умолчанию" без сравнения. Графики —
`reports/figures/calibration_curve.png`.

## Feature Ablation (раздел 19)

LogisticRegression, TEST:

| Эксперимент | Accuracy | Log Loss | Brier | ROC-AUC |
|---|---:|---:|---:|---:|
| A: Elo only | 0.5873 | 0.6761 | 0.2416 | 0.6207 |
| B: Elo + recent form | 0.5873 | 0.6815 | 0.2442 | 0.6069 |
| C: Elo + recent form + rest | 0.5850 | 0.6846 | 0.2454 | 0.6087 |

**Recent form и days_since_last_match НЕ добавляют сигнал в текущей
выборке — ROC-AUC монотонно снижается от A к B.** Это согласуется с
ограничением из раздела "Dataset" выше: квартальное сэмплирование рвёт
непрерывность именно тех признаков, которые сильнее всего зависят от
полноты недавней истории команды (`recent_winrate` считается по последним
5 матчам В НАШЕЙ ВЫБОРКЕ, не в реальной истории команды — если часть
недавних реальных матчей команды не попала в сэмпл, признак вычисляется по
неполному/смещённому окну). **Нельзя сделать вывод "recent form не имеет
predictive value в принципе"** — только "не добавляет значимого сигнала
поверх Elo НА ЭТОМ сэмплированном датасете". Это главный кандидат для
перепроверки на непрерывной (не quarterly-gapped) выборке, см. Conclusion.

## Walk-forward backtest (раздел 15-17)

Expanding window по кварталам: обучение на всех строках СТРОГО раньше
начала периода → прогноз всего периода (out-of-sample) → период
добавляется в обучающую выборку для следующего шага. Первые 2 квартала
(2021-Q1, 2021-Q2) пропущены — недостаточно данных для честного обучения
(`MIN_TRAIN_ROWS=200`). 21 период предсказан, все — строго out-of-sample.

| Модель | mean accuracy | std accuracy | mean log_loss |
|---|---:|---:|---:|
| **Elo only** | **0.5568** | 0.0437 | **0.6884** |
| Logistic Regression | 0.5381 | 0.0440 | 0.7166 |
| CatBoost | 0.5135 | 0.0428 | 0.7310 |

**Тот же порядок, что на единственном split, устойчиво на 21 периоде**:
Elo only > LogReg > CatBoost. Это заметно усиливает доверие к находке
"Elo-only baseline лучше" — она не артефакт одного случайного разбиения.
Ни один период не дал экстремально высокую (>70%) точность — согласуется
с честной, не переобученной оценкой (раздел 34: результат 55-58% — это
реалистичный честный результат, не повод считать эксперимент неудачным).
Полная таблица по каждому кварталу — `reports/experiments/phase6_walk_forward.json`,
график — `reports/figures/walk_forward_performance.png`.

## Team leakage check (раздел 22)

953 уникальных команды в датасете, матчей на команду: min=1, median=3,
max=70 — очень длинный хвост (большинство команд сыграли считанные матчи в
выборке, что опять же следствие квартального сэмплирования, не полной
истории). На TEST (CatBoost calibrated): матчи между двумя "частыми"
командами (топ-25% по числу матчей) — accuracy 0.4867 (n=300); матчи с
хотя бы одной "редкой" командой — accuracy 0.4894 (n=141). **Различие
незначимо** (обе метрики близки к случайности, что отражает слабость самой
CatBoost-модели на этом фолде, а не специфичный team-leakage эффект).

## Cold start (раздел 23)

TEST: 68 матчей с хотя бы одной командой без истории
(`matches_played_before == 0`), 373 матча с обеими "известными" командами.
CatBoost (calibrated): cold-start accuracy 0.5147 (n=68), known-team
accuracy 0.4826 (n=373). Cold-start НЕ хуже known-team — ожидаемо, т.к.
cold-start матчи предсказываются как Elo=1000 (нейтрально) с обеих сторон,
что при в целом слабой предсказательной силе модели не сильно отличается
от predictions на "известных", но плохо предсказуемых командах.

## Error Analysis (раздел 31)

Топ ошибок CatBoost (calibrated) на TEST — полный список в выводе
`scripts/phase6_pipeline.py` и `reports/experiments/phase6_baseline.json`.
Наблюдение: калиброванные вероятности CatBoost сильно дискретизированы —
многие из самых уверенных ошибок дают ОДИНАКОВОЕ значение `P(radiant)=0.688`
для очень разных `elo_difference` (от -141.9 до +90.2). Это указывает на
малое число различимых "листьев"/уровней вероятности у модели с глубиной 4
и всего 3 признаками на ~2000 строк обучения — ещё один симптом того, что
CatBoost в текущей конфигурации не использует свою гибкость продуктивно на
этом маленьком, малопризнаковом датасете (согласуется с тем, что он хуже
Elo-only и по одиночному split, и по walk-forward). Ни один из
проанализированных случаев не использует информацию, недоступную на
prediction time (проверено вручную по колонкам `elo_difference`/`form_diff`
— всё pre-match).

## Conclusion

### Есть ли в Feature Set 0 устойчивый out-of-sample predictive signal?

**Да, слабый, но устойчивый и не случайный.** Elo-only baseline даёт
ROC-AUC 0.62 на едином split И mean accuracy 0.557 (против ~0.50 у
random/majority) на 21 независимом walk-forward периоде — это статистически
не шум (`std_acc=0.044`, разброс не пересекает 0.50 систематически в
минус). Это ЧЕСТНЫЙ, скромный результат (раздел 34: "50-53% — не провал,
60-70% — не автоматический успех") — здесь ближе к 55-59%, что для
предсказания исхода профессионального Dota 2 матча по одному числу (разница
Elo) не тривиально, но далеко от "решённой задачи".

Более сложные модели (LogReg с 3 признаками, CatBoost) **не улучшили**
результат Elo-only baseline — ни на едином split, ни на walk-forward. Это
не аргумент "признаки бесполезны", а сильный сигнал, что (а) наш способ
получения многолетней истории (quarterly-gapped sampling) искажает именно
те признаки, которые больше всего выигрывают от непрерывности
(`recent_winrate`, `days_since_last_match`), и (б) CatBoost с 3 признаками
на ~2000 строк не имеет пространства для содержательного нелинейного
взаимодействия — его гибкость здесь скорее шум, чем сигнал.

### Что является следующим наиболее перспективным источником сигнала?

В порядке приоритета:

1. **Непрерывная (не сэмплированная) история матчей хотя бы для одного
   ограниченного периода** (например, полный 2024-2026 без квартальных
   разрывов) — чтобы честно проверить, действительно ли `recent_form`/
   `days_since_last_match` не несут сигнала, или это артефакт текущей
   методологии сбора данных. Это прямая, дешёвая (без новых признаков)
   проверка ПЕРЕД любым усложнением модели.
2. **team identity/roster continuity** — `reports/team-identity-issues.md`
   и raздел 14 Phase 5 показали, что roster reconstruction из
   `match_players` технически осуществим; состав команды (не просто
   `team_id`) может быть значимо предиктивнее текущего Feature Set 0.
3. **Draft/picks_bans** — сознательно НЕ добавлен в этой фазе (раздел 32
   задания), явный кандидат для отдельного эксперимента Phase 7+, данные
   уже частично доступны в схеме (`picks_bans`), хотя bulk-исторический
   backfill этой сессии (`OpenDotaExplorerSource`) их не собирал —
   потребует либо точечного дозапроса `/matches/{id}` для выбранных
   match_id, либо повторного backfill с полным набором данных.
4. **Head-to-head история** — упомянута в `docs/features.md` как
   Feature Set 1+, не реализована; на small-n team-pairs (median 3 матча
   на команду в текущей выборке) вряд ли даст сигнал БЕЗ более плотной
   истории (см. пункт 1).

Рекомендация: прежде чем расширять feature set (draft, roster), стоит
устранить методологическое ограничение раздела "Dataset" — квартальные
разрывы — иначе новые признаки будут оцениваться на той же искажённой
основе, и результат ablation останется неинформативным.

# PHASE 6 SUMMARY

Честный результат: **слабый, но статистически устойчивый predictive signal
в Feature Set 0**, полностью объясняемый Elo — более сложные признаки/модели
в текущей конфигурации данных сигнал не улучшают. Leakage не обнаружена (5
независимых проверок). Walk-forward подтверждает результат на 21
независимом периоде, не на одном split.

Следующий рекомендованный шаг — не draft/roster (пока), а устранение
quarterly-gap ограничения выборки, чтобы честно перепроверить
`recent_form`/`rest`-признаки на непрерывной истории, прежде чем
усложнять feature set дальше.
