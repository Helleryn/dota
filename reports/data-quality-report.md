fixture mode (`--source fixtures`), не через живой запрос к OpenDota — сеть
к `api.opendota.com` недоступна из текущей среды (см.

доступом в интернет — структура этого отчёта (и генерирующий его код)

## Data-quality находки (обнаружены реальным прогоном, не гипотетические)

1. **Реальный пробел в пространстве `hero_id`.** При первом прогоне с
   произвольно сгенерированными `hero_id` в fixtures пайплайн упал с
   `ForeignKeyViolation` — `hero_id=24` не существует в справочнике
   `dotaconstants` (у Dota 2 есть исторические разрывы ID героев, см.
   `src/normalization/data/heroes.json`: 28 пропущенных ID в диапазоне
   1-155). Это **реальная особенность данных**, не артефакт fixture —
   такая же ситуация возможна и с живым OpenDota, если наш вендоренный
   справочник героев устареет относительно новых патчей. **Действие**:
   пайплайн исправлен так, чтобы `IntegrityError` на уровне одного матча
   не ронял весь batch (см. `phase5-summary.md`, раздел "проблемы").
2. **Детальный ответ (`/matches/{id}`) недоступен для части матчей.**
   6-7 из 14 матчей в fixture намеренно не имеют детального ответа
   (реалистичный сценарий — не для каждого матча парсинг/детали доступны
   сразу у источника, `docs/data-feasibility.md`). Пайплайн корректно
   сохраняет ядро матча (результат, команды, patch) и помечает
   отсутствие драфта/состава как `warning`, не `error`.
3. **`league_name` не сохраняется в normalized-слое.** `RawMatch` не несёт
   поле с именем лиги (только `league_id`/`league_tier`) — `leagues.name`
   в БД остаётся `NULL` для матчей, загруженных только через `/proMatches`.
   Известное ограничение MVP, не критично для ML-признаков (имя лиги нигде
   не используется как feature), но снижает читаемость отчётов/UI. Нужен
   отдельный sync `/leagues` с сохранением `name`, аналогично `heroes`/`patches`.
