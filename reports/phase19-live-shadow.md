# PHASE 19 — live shadow: три статуса вместо одного (PART Q)

Запуск 2026-08-27. Источник — bo3.gg, `discipline_id = 4` (Dota 2).

---

## 1. Что изменилось относительно Phase 18

Phase 18 держала **один** статус, и он смешивал три разных вопроса.
Здесь их три:

| Статус | Значения | Отвечает на вопрос |
|---|---|---|
| `roster_status` | FULL / PARTIAL / UNKNOWN | сколько игроков сопоставлено |
| `lineup_status` | CONFIRMED / PREDICTED / UNKNOWN | **откуда взят** состав |
| `prediction_status` | READY / PARTIAL_DATA / ABSTAIN | что система готова выдать |

Разделение не косметическое. Полный состав, взятый из реестра «на
сегодня», — это `FULL + PREDICTED`, а вовсе не подтверждённый состав.
Phase 18 такую разницу выразить не могла, и полнота выглядела бы как
достоверность.

### Три нуля — главный результат запуска

`FULL = 0`, `CONFIRMED = 0`, `READY = 0`. Ни один из трёх верхних
уровней не достигнут ни разу, и каждый ноль имеет свою причину:

| Ноль | Причина |
|---|---|
| `FULL = 0` | матчей с десятью сопоставленными игроками не существует (Phase 18, подтверждено здесь) |
| `CONFIRMED = 0` | **источника, объявляющего состав на конкретный матч, не существует** |
| `READY = 0` | требует полного состава; следует из первого |

Ветка `CONFIRMED` оставлена в коде явной, а не выброшена, — чтобы было
видно: она недостижима не по недосмотру реализации, а потому что данных
такого рода не публикует никто.

## 4. Чего этот запуск НЕ доказывает

* **Прогнозы не проверены исходом.** Матчи начинаются через 22–55 часов.
* **Калибровка не применена** (`calibration_version = "none"`), потому
  что калибровочного окна для режима частичного состава ещё не
  накоплено. Указано явно, а не подставлено молча.
* **Вероятность считается Elo-формулой**, а не замороженной моделью: у
  той пять входов, доступны не все. Это прототип режима.
* **Реестр `proPlayers` — снимок «сегодня».** Для живого прогноза
  (T = сейчас) законно; в историческом replay запрещён и не применяется.

---

## 5. Что этот запуск подтверждает из case study

Case study Vision vs Spirit шёл при `roster_status = FULL` (5/5 с обеих
сторон) — то есть в условиях, **которых живой конвейер не достигает ни
разу**. Полный состав там взят из post-match таблицы, а не получен
источником заранее.

Значит числа case study — это верхняя граница того, что доступно живому
режиму, а не его типичный случай.
