## 0. НАЙДЕННАЯ МЕТОДОЛОГИЧЕСКАЯ ПРОБЛЕМА В PHASE 8

Задание требует не скрывать методологические дефекты предыдущих фаз.
Аудит `scripts/phase8_pipeline.py` выявил два связанных дефекта.

### Дефект 1 — feature selection по TEST

```python

    return m, m.evaluate(test, test["target"])   # <- метрика с TEST

# scripts/phase8_pipeline.py:236
best_a_name = max(a_experiments, key=lambda k: -results[k]["log_loss"])
```

`results[...]` заполнялись метриками **на TEST**, и по ним выбиралась
лучшая A-конфигурация, которая затем вошла в состав `B5` и в сравнение
CatBoost. Это выбор признаков по тестовой выборке — ровно то, что
запрещено разделом «Защита от feature overfitting».

### Дефект 2 — VALIDATION создавался, но не использовался

`train, val, test = split(df)` — `val` фигурирует только в печати размера
и в реестре. Ни одно решение по нему не принималось. Все 11 конфигураций
сравнивались на TEST, что даёт оптимистическое смещение «лучшей» из них.

### Что из результатов Phase 8 уцелело, а что нет

| Результат Phase 8 | Статус |
|---|---|
| **A1 = Baseline + `player_elo_mean`, +2.02 pp, CI [+1.32,+2.67], p<0.0001** | **Уцелел.** Это ОДИН заранее объявленный признак — центральная гипотеза фазы, а не победитель отбора среди многих. |
| Walk-forward 5/5 лет | **Уцелел.** Модель переобучается на каждый год, конфигурация фиксирована заранее. |
| Декомпозиция по длине истории `team_id` (+3.32 / +2.13 / +1.06 pp) | **Уцелела.** Диагностика, а не отбор. |
| **B5 = +2.50 pp** и заявление «лучшая конфигурация» | **НЕ уцелело.** Состав B5 выбран по TEST ⇒ значение смещено вверх. |
| Сравнение 11 конфигураций между собой на TEST | **НЕ уцелело** как основание для выбора. |

**Вывод:** заголовочный результат Phase 8 (player-Elo даёт сигнал) остаётся
в силе; конкретное число «+2.50 pp для полной модели» — нет. Phase 9
перепроверит его по корректному протоколу.

### Исправление протокола, обязательное для Phase 9

1. **Любой выбор** (какая агрегация лучше, какая мета-схема лучше, состав
   финальной модели) делается **только по VALIDATION**.
2. **TEST трогается один раз**, в самом конце, для заранее
   зафиксированного набора моделей. Число обращений к TEST фиксируется в
   отчёте.
3. Для каждого семейства сообщаются **и VAL, и TEST** метрики, чтобы был
   виден масштаб оптимистического смещения при отборе.

## 3. Признаки, которые реально можно построить

### PART A — Roster representation (HIGH)
`mean`, `sum`, `median`, `min`, `max`, `std`, `spread(max−min)` от player-Elo
пятёрки; weakest-link и star-player комбинации. Данные есть на 93.8%
матчей. Каждая агрегация тестируется **отдельно**, не «feature soup».

### PART B — Roster delta (HIGH)
`roster_strength_delta` (сила текущей пятёрки минус сила предыдущей),
`player_replacement_delta` (Elo пришедшего минус Elo ушедшего),
`n_recent_replacements`, `cumulative_recent_roster_delta`, окна 7/14/30 дней.
Выборка: 33 735 событий — достаточно.

### PART C — Current five vs Team Elo (HIGH)
`current_five_strength − team_elo`. Частично уже проверено в Phase 8
(`roster_vs_team_delta`), но по дефектному протоколу — переоценить.

### PART D — Player Elo и team identity (HIGH, диагностика)
Повтор декомпозиции Phase 8 по длине истории `team_id` + анализ поведения
около трансферов. Без причинных выводов.

### PART E — Synergy игроков (MEDIUM)
Пары и пятёрка: матчи вместе, shrunk winrate, performance относительно
ожидаемого. Обязательно Beta-Binomial shrinkage (Phase 8 уже так делает).

### PART G-N — Draft/meta (HIGH для hero strength, MEDIUM для остального)
- 5 схем силы героя для сравнения: global / same-patch / recent-window /
  exp-decay / patch+decay — **все на одном evaluation set** (Part H).
- **Pick/ban rate (Part I)** — новое, баны ещё не использовались.
- Player×Hero (Part J), Team×Hero (Part K), synergy (L), counters (M),
  собранный Draft Advantage (N).

### PART O — Draft state (MEDIUM)
`ord` доступен ⇒ pick order, ban order, first-pick side.

### PART P — Meta state (LOW приоритет)
Phase 8 уже показала: глобальный скаляр одинаков для обеих команд и
линейной моделью не используется. Проверять только как interaction/в
CatBoost, и только если останется бюджет.

## 4. Признаки, опасные с точки зрения leakage

| Признак | Риск | Решение |
|---|---|---|
| `lane_role` текущего матча | **Прямая утечка** (post-match) | Запрещён полностью |
| `notable_players.fantasy_role` | **Временная утечка** (снимок «сегодня» применяется к прошлому) | Запрещён |
| Любая игровая статистика матча (KDA/GPM/XPM/damage) | Прямая утечка | Запрещена (унаследовано из Phase 8) |
| Time decay | Затухание не должно «подсматривать» вперёд | Ленивое затухание строго от прошлых наблюдений + отдельный adversarial-тест |
| Состав текущего матча из `match_players` | **Соглашение, не утечка** | Сохраняется соглашение Phase 7/8; в проде требует анонса лайнапа. Документируется в каждом отчёте |
| Pick/ban текущего матча | Post-draft | Только MODE B, запрещено в MODE A |

## 5. Эксперименты, которые нужно провести

**Блок 1 (PART A):** 8 отдельных сравнений `Baseline vs Baseline + одна
агрегация`. Отбор лучшей — **по VALIDATION**.

**Блок 2 (PART B/C):** roster delta и current-five-vs-team-Elo, отдельно.

**Блок 3 (PART D):** диагностика по длине истории команды и около
трансферов.

**Блок 4 (PART H):** 5 схем силы героя, сравнение на одном наборе, отбор по
VALIDATION.

**Блок 5 (PART I/J/L/M):** pick/ban rate, player-hero, synergy, counters —
каждое отдельно от baseline.

**Блок 6 (PART N):** собранный Draft Advantage из компонентов, победивших на
VALIDATION.

**Финал:** один прогон по TEST для заранее зафиксированного списка моделей +
walk-forward + block bootstrap + McNemar.

## 6. Эксперименты, требующие внешних источников

## 7. Эксперименты, которые невозможно провести честно

| Эксперимент | Почему |
|---|---|
| Role-adjusted player strength | Нет pre-match источника ролей (раздел 2). Вывод позиции из GPM данного матча дополнительно загрязнён исходом — проигрывающая команда фармит меньше |
| «Player X вызвал улучшение команды» | Причинность не устанавливается наблюдательными данными; shared-credit Elo делит исход поровну по построению |
| Higher-order synergy (тройки/пятёрки героев) | Комбинаторный взрыв при 123+ героях; выборка не позволяет |

## 8. Критерий KEEP / REMOVE / RESEARCH FURTHER

`KEEP` присваивается только при выполнении **всех**:
положительный эффект на TEST (при том, что отбор шёл по VAL) **и** CI,
исключающий 0, **и** устойчивость в walk-forward (≥4/5 лет), **и**
отсутствие утечки, **и** покрытие ≥80% матчей, **и** интерпретируемое
направление коэффициента.

Рост Accuracy на одном split — **не основание** для KEEP.
