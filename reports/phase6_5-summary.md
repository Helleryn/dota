# PHASE 6.5 SUMMARY — Continuous History + Statistical Validation

Дата: 2026-08-25. Продолжение `reports/phase6-summary.md`. Все цифры —
из реальных прогонов `scripts/backfill_continuous.py`,
`scripts/phase6_5_pipeline.py`. Реестр: `reports/experiments/phase6_5_continuous.json`.
Графики: `reports/figures/phase6_5_*.png`. `git commit 263f9a1` (код Phase

документа). `random_seed=42` везде.

## 1. Objective

Проверить, действительно ли `recent_form`/`rest`-признаки не несут
predictive signal поверх Elo (Phase 6, ablation на квартально
сэмплированных данных), или это артефакт методологии сбора данных
(квартальные разрывы истории). Условие: строгий out-of-sample протокол,
единый evaluation set для всех сравниваемых моделей, статистическая
значимость через temporal-aware bootstrap, без перехода к draft/roster.

## 2. Data coverage

Полный отчёт — `reports/continuous-data-coverage.md`. Кратко: непрерывная
(без квартальных разрывов) история pro+premium tier, 2021-01-01 —
2026-08-24, **117 371 матч**, 0 дублей, ни одной пустой недели/месяца
(за вычетом boundary-артефактов на границах диапазона). Получена за ~14
минут через `OpenDotaExplorerSource` (6 bulk-запросов `/explorer`, по
одному на год) — предположение Phase 6 о необходимости sampling оказалось
неверным при экспериментальной проверке: `/explorer` возвращает целый год
без пагинации и без обрезки.

**Важная находка, не влияющая на методологию, но на интерпретацию**:
`premium`-tier практически исчез после 2023 (замещён ростом `excluded`),
вероятно, из-за прекращения Valve DPC после TI2023. `PRO_LEAGUE_TIERS`
определение НЕ менялось.

Leakage-safety нового модуля перепроверена adversarial-тестами
(`tests/leakage/test_multi_window_features_leakage.py`, 4 теста, PASS) —
не предполагалась "по аналогии" с уже проверенным `feature_set_0.py`.

## 4. Methodology

- **Chronological split**: 70/15/15 по индексу отсортированных строк.
  TRAIN 2021-01-01 — 2024-06-12 (n=82 159), VALIDATION 2024-06-12 —
  2025-04-08 (n=17 606), TEST 2025-04-08 — 2026-08-24 (n=17 606). Без
  overlap (проверено программно).
- **Единый evaluation set (раздел 14)**: cold-start строки (хотя бы одна
  команда без предыдущих матчей) исключены из TRAIN/VAL/TEST ОДИН РАЗ,
  единообразно для ВСЕХ моделей A-G — TRAIN n=78 389, VAL n=16 510, **TEST
  n=16 331**. Все метрики ablation ниже — на этом одном TEST.
- **Elo K подбирается на VALIDATION, не на TEST** (раздел 19-20) — см.
  ниже.
- **Форма окна для составной модели G** также выбрана по VALIDATION
  log_loss, не по TEST.

## 10. Statistical Uncertainty (раздел 16-18)

Block bootstrap, `block_size=20` (смежные блоки матчей, не отдельные
строки — раздел 17), `n_bootstrap=2000`, `seed=42`, TEST (n=16 331,
817 блоков).

| Метрика (Elo) | Point | 95% CI |
|---|---:|---|
| Accuracy | 0.5974 | [0.5891, 0.6056] |
| Log Loss | 0.6638 | [0.6596, 0.6683] |
| Brier | 0.2357 | [0.2338, 0.2378] |

**Effect size, Elo accuracy − 0.5**: **+7.91 pp**, 95% CI **[+6.86, +8.98]
pp** — CI полностью исключает 0. **Elo статистически значимо лучше
случайного угадывания**, не шум.

**log_loss(Elo) − log_loss(Full model)**: **+0.0030**, 95% CI **[+0.0020,
+0.0041]** — полностью положительный интервал (log_loss Elo систематически
ВЫШЕ = хуже, чем у Full model) → **добавление Form3 статистически значимо
улучшает log_loss**, не просто разница точечных оценок.

**McNemar exact test (Elo vs Full model, paired на TEST)**: discordant
pairs = 1212 (Elo-верно/Full-неверно = 559, Full-верно/Elo-неверно = 653),
**p = 0.0075** — статистически значимое различие (p < 0.05) в пользу Full
model на реальном объёме discordant-пар, не совпадение.

**Вывод раздела 10**: Elo — реальный, статистически подтверждённый сигнал
(не только на точечной оценке). Добавление Form3 — тоже статистически
значимое улучшение, тремя независимыми методами (block bootstrap accuracy
diff, block bootstrap log_loss diff, McNemar), не только "чуть лучше на
одном split".

## 16. Limitations

1. **Смещение tier-классификации 2024+** (раздел 2) — интерпретация
   temporal stability для 2024-2026 требует осторожности; возможно
   изменение состава выборки, не только "реального" изменения
   предсказуемости.
2. **Block bootstrap с фиксированным `block_size=20`** — не проводился
   sensitivity-анализ по размеру блока (например, 10 vs 50) — при другом
   размере блока ширина CI могла бы немного измениться (шире при бОльших
   блоках). Точечные оценки не изменились бы.
3. **Cold-start исключение (раздел 14)** отбрасывает ~11-13% строк — это
   МЕНЯЕТ распределение (первые матчи команд обычно менее предсказуемы),
   поэтому абсолютные метрики здесь НЕ напрямую сравнимы с Phase 6 (там
   cold-start не исключался единообразно из всех сравнений).
4. **`excluded`-tier полностью исключён** — не проверено, есть ли внутри
   него матчи сопоставимого с `professional` качества (см. `reports/continuous-data-coverage.md`).
5. **K-analysis** протестировал только 5 значений K на равномерной сетке
   (16-64) — не исключено, что оптимум лежит вне этого диапазона (K<16),
   не проверялось.

## 17. Decision (раздел 29)

| Признак | Решение | Обоснование |
|---|---|---|
| **Elo** | **KEEP** | CI accuracy-vs-0.5 полностью положителен [+6.86, +8.98] pp; устойчив по годам (0.577-0.616), по патчам (0.563-0.619), в walk-forward (5/5 лет > 0.5); хорошо откалиброван без доп. обработки |
| **Recent Form (окно 3)** | **KEEP** | McNemar p=0.0075 vs Elo-only; log_loss diff CI [+0.0020, +0.0041] полностью в пользу Form; консистентно лучше Elo в 5/5 walk-forward лет; воспроизведено на непрерывных данных (в отличие от Phase 6 quarterly-sampled, где сигнал не проявился) |
| **Recent Form (окна 10, 20)** | **RESEARCH FURTHER** | Хуже окна 3 на TEST и VALIDATION одновременно — не улучшают Elo (E практически не отличим от A). Не "плохие" в абсолютном смысле, просто не добавляют поверх Elo+Form3 |
| **Rest (days_since_last_match, matches_last_N_days)** | **REMOVE (из текущего Feature Set)** | F идентичен A с точностью до шума, G идентичен B — Rest не даёт измеримого прироста НИ В ОДНОЙ комбинации на непрерывных данных. Это не sampling-артефакт (данные непрерывны) — правдоподобно, что "недавняя усталость"/паузы между матчами просто не предсказывают исход на нашем уровне признаков |

## 18. Recommended next experiment

1. **Обновить Feature Set 0/1** для будущего сервиса: `Elo (K=16) +
   recent_form_3`, убрать `days_since_last_match` как признак с нулевым
   подтверждённым вкладом (можно оставить как diagnostic/monitoring
   признак, не как model input).
2. **Draft/roster features (раздел 32 — сознательно НЕ начаты здесь)** —
   теперь оправданы: базовый Elo+Form3 сигнал статистически подтверждён и
   стабилен, есть на чём измерять инкрементальный вклад draft отдельным
   ablation-экспериментом (тот же протокол: единый evaluation set, block
   bootstrap, McNemar).
3. **Исследовать 2024+ tier-сдвиг** отдельно от ML-экспериментов — оценить,
   есть ли способ надёжно включить часть `excluded`-tier матчей 2024-2026
   без потери качества (потенциально увеличит выборку последних лет в 2-3
   раза).
4. **Sensitivity-анализ block bootstrap** (`block_size` 10/20/50) — дёшево,
   повышает доверие к CI перед тем, как эти цифры используются для
   решений о production-качестве сервиса.

# PHASE 6.5 SUMMARY

## Критический вопрос 1

> "Если завтра мы запустим prediction service только с Elo, насколько
> честно мы можем ожидать, что он будет работать лучше случайного
> угадывания?"

**Да, статистически надёжно.** Accuracy 59.7% против 50% случайного,
95% CI на разницу [+6.9, +9.0] процентных пункта — интервал НЕ включает
ноль, подтверждено на 16 331 матчах TEST (block bootstrap, temporal-aware),
устойчиво по 5 годам walk-forward (ни один год не опускался к 50%), по 14
патчам (0.563-0.619), с хорошей калибровкой без дополнительной обработки.
Это скромный, но реальный и воспроизводимый edge, не шум одного split.

## Критический вопрос 2

> "Есть ли доказательства, что recent form/rest добавляют независимый
> predictive signal?"

**Recent form (короткое окно, 3 матча) — да, доказано трижды независимо**
(block bootstrap разницы log_loss, McNemar exact test, консистентность
5/5 лет walk-forward). Это ПРЯМОЕ опровержение вывода Phase 6
("recent_form не добавляет сигнал") — там сигнал маскировался квартальными
разрывами истории, не отсутствовал в принципе. **Rest — нет, не
доказано**: ни в одной из проверенных комбинаций (Elo+Rest, Elo+Form+Rest)
не дал измеримого улучшения, на тех же непрерывных данных, где Form3 его
дал — это не тот же артефакт методологии, а, вероятно, реальное отсутствие
сигнала в текущей формулировке признака.

Останавливаюсь здесь, как и требует задание. Жду решения по следующему шагу.
