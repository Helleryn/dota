# PHASE 13 — план: границы модели, неопределённость, калибровка, анализ ошибок

> План зафиксирован **до** экспериментов. Цель фазы — не поднять accuracy,
> а понять, **где текущей модели можно доверять, а где нельзя**.

---

## 0. Уточнение по «текущему frozen feature set»

В задании набор указан как три признака:
`elo_mean_diff`, `five_vs_team_elo_diff`, `hero_exp_decay_diff`.

Это KEEP-список **добавок** Phase 9, а не полный набор модели. Реально
обученная модель Phase 9/12 использует пять входов — три добавки плюс два
признака frozen baseline:

```
elo_difference, form_3_difference,            <- frozen baseline (Elo K=16 + Form3)
elo_mean_diff, five_vs_team_elo_diff, hero_exp_decay_diff   <- KEEP Phase 9
```

Именно этой пятёркой получены 0.6279 (Phase 9 TEST) и 0.6301 (Phase 12 TEST).

Расхождение фиксируется здесь, чтобы не выдавать за воспроизведение то, что
им не является. **PART A обязан воспроизвести обе версии** — пятёрку и
чистую тройку — и показать, что цифры задания соответствуют пятёрке.

## 1. Протокол (PART P)

| Правило | Как обеспечивается |
|---|---|
| Все решения — на VALIDATION | пороги отказа, отбор ковариат, конфигурация meta-модели |
| TEST — одно обращение | флаг `--final-test`, счётчик обращений в JSON |
| Baseline не меняется | Phase 9 модель переобучается тем же кодом, тем же seed |
| Отрицательные результаты не прячутся | каждая гипотеза получает вердикт, включая «не подтвердилась» |
| Negative control | в каждую матрицу экспериментов включается признак из шума |

Сплит прежний: 70/15/15 по `(start_time, match_id)`, `random_seed=42`,
block bootstrap с временными блоками (блок=20, n=2000).

## 2. Что измеряется

### PART B — калибровка
Log Loss, Brier, ECE, MCE, reliability curve, calibration slope и intercept
(логистическая перекалибровка `y ~ logit(p)`: slope=1, intercept=0 —
идеально откалибровано). Разрезы: overall, по годам, по бинам уверенности,
отдельно фавориты (`p>0.5`) и андердоги.

### PART C — что такое уверенность
Проверяется явно сформулированное сомнение задания: достаточно ли `|p−0.5|`.
Кандидаты в ковариаты неопределённости — **все pre-match**:

| Ковариата | Источник |
|---|---|
| число прошлых матчей команды (min/max сторон) | `multi_window_features` |
| число прошлых матчей игроков (min по пятёрке) | player-Elo движок |
| новизна состава (матчей вместе, возраст состава, число замен) | `roster_features` |
| Elo gap, player-Elo gap | baseline + `roster_representation` |
| объём выборки по героям, новизна героев | `hero_strength_schemes` |
| дни с релиза патча | `patches` |
| разреженность признаков (доля нулевых) | вычисляется |
| расстояние до training-распределения | Mahalanobis по признакам модели |

### PART D — meta-модель P(error)
Target: `1` если модель ошиблась. Обучается на TRAIN, отбирается на
VALIDATION. **Единственное жёсткое ограничение — все входы известны до
матча.** Никакого исхода, пост-матчевой статистики, будущих составов и
будущей статистики героев.

### PART E/F/G — сложность, таксономия, монотонность
Дециль сложности → accuracy/log loss. Таксономия ошибок с обязательной
категорией **high confidence + wrong**. Проверка монотонности accuracy по
децилям уверенности.

### PART H/I — coverage-risk и механизмы отказа
Полная кривая покрытия 100%…10% с шагом 5 пп: accuracy, log loss, Brier,
калибровка. Сравнение пяти механизмов отказа: `|p−0.5|`, составной
confidence score, оценка `P(error)`, разногласие ансамбля, uncertainty score.

### PART J/K/L/M — сдвиг распределения и пределы player-Elo
Дистанция до training-распределения; окна 1/3/7/14/30 дней после патча;
0/1/2/3/5 замен в составе; стабильность player-Elo после перехода игрока.

### PART N/O — ансамбли и потолок
LogReg + CatBoost, взвешенное усреднение; главный вопрос — предсказывает
ли **разногласие моделей** ошибку. Затем эмпирическая оценка потолка:
если несколько разных семейств моделей сходятся к одному результату — это
свидетельство информационного потолка.

## 3. Гипотезы (до экспериментов)

| # | Гипотеза | Предсказание | Опровергается, если |
|---|---|---|---|
| **G1** | `\|p−0.5\|` — не полная мера уверенности | ковариаты объёма данных добавляют к предсказанию ошибки | AUC meta-модели по ковариатам не выше, чем по `\|p−0.5\|` |
| **G2** | Ошибку можно предсказать заранее | AUC meta-модели P(error) заметно выше 0.5 | AUC ≈ 0.5 |
| **G3** | Новый состав повышает риск | accuracy падает с ростом числа замен | различий нет |
| **G4** | Смена патча повышает риск | хуже метрики в первые дни патча | различий нет |
| **G5** | Сдвиг распределения связан с ошибками | accuracy падает с ростом дистанции | связи нет |
| **G6** | Разногласие моделей — сигнал неопределённости | ошибка чаще там, где модели расходятся | связи нет |
| **G7** | Потолок информационный, а не модельный | разные семейства сходятся к одному результату | одно семейство заметно впереди |
| **G8** | Калибровка держится в разрезах | slope≈1, intercept≈0 в подгруппах | систематическое смещение в подгруппе |

### Что уже известно и НЕ проверяется заново
* Калибровка в целом хорошая (Phase 12: ECE 0.0091 VAL / 0.0207 TEST) —
  проверяется её **устойчивость по разрезам**, а не сам факт.
* Селективный прогноз работает (Phase 12) — строится **полная кривая**,
  а не единичные точки.
* Признаки драфта избыточны (Phase 12) — не пересматриваются.

## 4. Карта утечек (PART Q)

Главный новый риск фазы — **meta-модель P(error) видит будущее**.
Проверяется адверсариально:

| # | Сценарий |
|---|---|
| Q1 | информация об ошибке модели просочилась во вход meta-модели |
| Q2 | калибровка подобрана по будущим матчам |
| Q3 | будущая сила команды в ковариатах |
| Q4 | будущая сила игрока |
| Q5 | будущая мета |
| Q6 | будущий патч (дата релиза известна, но статистика патча — нет) |
| Q7 | пост-матчевый состав |
| Q8 | пост-матчевая статистика героев |
| Q9 | статистика распределения посчитана с участием VAL/TEST |
| Q10 | порог отказа подобран на TEST |

Формальный критерий тот же — **prefix-stability**.
