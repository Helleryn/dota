## 3. Гипотезы

Все — механизмы, а не наборы признаков. Для каждого сказано, **почему он
может добавить информацию сверх player-Elo**.

### H1 — индивидуальная неопределённость игрока (PART A)

**Механизм.** player-Elo — точечная оценка. Игроки 1600 с 1200 матчами и
1600 с 15 матчами для модели тождественны. Если оценка ненадёжна, разумно
**притянуть сигнал силы к нулю**, а не доверять ему полностью.

**Почему сверх player-Elo.** Величина ортогональна уровню по построению:
это дисперсия оценки, а не её среднее.

**Формализация.** Эффективное число игр с затуханием
`n_eff(p,T) = Σ 0.5^(Δt/hl)`; отклонение рейтинга
`RD(p,T) = RD₀ / sqrt(1 + n_eff)`. Индивидуально по игроку, **без общей
дельты на пятёрку**.

Признаки: `rd_mean_diff`, `rd_max_diff`, и главный —
`elo_mean_diff_attenuated = elo_mean_diff · a`, где
`a = n̄_eff/(n̄_eff + κ)`.

**Adversarial:** при переходе игрока в другую команду его RD обязан
сохраниться; `team_id` не должен его менять.

### H2 — сила по позициям (PART B)

**Механизм.** Phase 9 отвергла **неупорядоченные** меры разброса (`std`,
`spread` — на уровне шума). Позиционное сопоставление — **другой**
механизм: не «насколько разбросаны мои игроки», а «мой керри против
твоего керри».

**Почему сверх player-Elo.** Составы A = 1700/1700/1700/1400/1400 и
B = 1600×5 имеют одинаковое среднее; при матчапе против C = 1600×5
позиционные разницы у A и B различны, а `elo_mean_diff` — нет.

**Формализация.** Позиция — PREDICTED (мода прошлых позиций игрока,
Phase 11, 83.5%), статус **не повышается** до CONFIRMED.
Признаки: `pos_diff_1…5`, `pos_bottleneck = min`, `pos_best = max`,
`pos_imbalance = max − min`.

> Заранее объявленная зависимость: `Σ pos_diff_i = 5·elo_mean_diff`,
> поэтому пять позиционных разниц **не ортогональны** базе. Независимую
> информацию может нести только их *распределение*, и проверять надо
> именно incremental value, а не корреляцию.

### H3 — временная актуальность силы (PART F)

**Механизм.** Elo — случайное блуждание без забывания. Игрок, бывший 1800
два года назад и не игравший с тех пор, сегодня не 1800.

**Почему сверх player-Elo.** Признак — **разность** между затухающей и
незатухающей оценкой, то есть ровно та часть, которую player-Elo не
выражает.

**Формализация.** `elo_mean_decayed_diff` (player-Elo, притянутый к базе
1000 с полураспадом hl), `recency_gap = decayed − plain`,
`days_since_last_match_max`.

### H4 — сыгранность состава (PART F/synergy)

**Механизм.** Не «насколько сильны игроки», а «сколько они играли вместе
именно этой конфигурацией».

**Почему сверх player-Elo.** player-Elo агрегирует исходы независимо от
того, с кем игрок их получил.

**Формализация.** `pair_games_mean/min` — затухающее число совместных
матчей по 10 парам внутри пятёрки; `core3_games` — по тройкам.
**Обязательно:** `synergy_residual` — та же величина после вычитания
предсказания по player-Elo, чтобы отделить сыгранность от силы.

### H5 — новизна пятёрки относительно её истории (PART G)

**Механизм.** Не «стабильность» (Phase 7 отвергла), а **похожесть текущей
пятёрки на конфигурации, на которых накоплена история**. Якорь —
идентичность игроков, **не** `team_id` (Phase 10: фрагментация реальна).

**Формализация.** `returning_players` — сколько из пятёрки играли в
предыдущем матче этой же пятёрки; `core_continuity` — размер
наибольшего сохранившегося ядра; `lineup_novelty = 1 − Jaccard` с
последней виденной пятёркой; `days_since_lineup_formation`.

## 5. Экспериментальный протокол

| | |
|---|---|
| **основная метрика** | **log loss на VALIDATION** |
| вторичные | accuracy, ROC-AUC, ECE, Brier, McNemar, 95% CI, walk-forward по годам |
| порог отбора | **Δlog loss > 1e-4**, объявлен заранее |
| сплит | хронологический 70/15/15, тот же, что во всех фазах |
| модель | LogisticRegression, seed=42 — как frozen, но **исследовательская версия поверх** |
| база сравнения | `PREMATCH_BASELINE` = 4 входа (pre-match режим) |
| обращений к TEST | **ровно 1**, в самом конце, на M6 |
| bootstrap | блочный, блок=20, n=2000, seed=42 |

### Ablation (PART J)

```
M0 = PREMATCH_BASELINE
M1 = M0 + H1 (uncertainty)
M2 = M0 + H2 (позиции)
M3 = M0 + H3 (актуальность)
M4 = M0 + H4 (сыгранность)
M5 = M0 + H5 (новизна)
M6 = M0 + только те, что прошли порог поодиночке
```

Никакого brute-force поиска по признакам.

### Redundancy audit (PART K)

Для каждого кандидата: корреляция с `elo_mean_diff`, `elo_difference`,
`form_3_difference`; incremental value; устойчивость по годам.

Правило: высокая корреляция **и** нет incremental value → **REMOVE**;
высокая корреляция **и** есть incremental value → **RESEARCH FURTHER**.

## 6. Критерии решения

| Вердикт | Условие |
|---|---|
| **KEEP** | Δlog loss > 1e-4 на VAL **и** подтверждено на TEST **и** 95 % CI не включает 0 |
| **RESEARCH FURTHER** | прошло VAL, но CI включает 0 либо неустойчиво по годам |
| **REMOVE** | не прошло порог на VAL |
| **NOT TESTABLE** | данных не существует |

**Phase 20 не обязана закончиться KEEP.** Если ни один механизм не даёт
независимого сигнала — это подтверждение G7 Phase 13 («потолок
информационный, а не модельный») и полноценный результат.
