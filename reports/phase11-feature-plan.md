## 1. Признаки: гипотеза → формула → риск → ожидание

### F1. PlayerHeroStrength — главный кандидат фазы

**HYPOTHESIS.** Способность игрока реализовать конкретного героя отличается
от средней силы этого героя, и это различие предсказуемо.

**DATA.** `match_players` (account_id, hero_id) + результат. Покрытие: 83.3%
player-match имеют ≥1 прошлую игру на герое, медиана 8.

**FORMULA.** Не сырой winrate (прямой запрет задания). Оценка **относительно
baseline героя**, с затуханием и сглаживанием:

```
ph_wr(P,H,t) = (decayed_wins(P,H) + m/2) / (decayed_games(P,H) + m)
h_wr(H,t)    = (decayed_wins(H)   + m/2) / (decayed_games(H)   + m)
PlayerHeroStrength(P,H,t) = ph_wr − h_wr
```

Признак матча = среднее по 5 игрокам стороны, затем разность radiant−dire.

**ЧТО ОЗНАЧАЕТ (PART X).** Не «игрок выиграл X% игр», а «оценка того,
насколько игрок превосходит ожидаемый уровень этого героя, с поправкой на
объём выборки и давность». При отсутствии истории признак равен ровно 0
(нет информации), а не 0.5.

**LEAKAGE RISK.** Низкий: счётчики обновляются строго после фиксации
признаков. Требует adversarial-теста на затухание.

**EXPECTED SIGNAL.** Умеренный. Обоснование ожидания: Phase 8 уже измеряла
грубый player-hero proficiency и получила +1.14 pp самостоятельно, но
коэффициент падал до +0.036 рядом с roster-признаками. Ожидаю, что
улучшенная формулировка (затухание + shrinkage + baseline героя) даст
больше, но **не жду прорыва** — информация частично уже в player-Elo.

### F2. Half-life sweep

**HYPOTHESIS.** Есть период полураспада, при котором player-hero сигнал
максимален; слишком короткий — шум, слишком длинный — устаревшая мета.

**FORMULA.** F1 при half-life ∈ {7, 14, 30, 60, 90, 180} дней.

**ОТБОР — ТОЛЬКО ПО VALIDATION.** Явное требование задания.

**EXPECTED.** Оптимум в районе 90-180 дней (в Phase 9 для героев победил 90),
но у player-hero выборки меньше → вероятен сдвиг к более длинным окнам.

### F3. PlayerRoleProfile / role-aware strength

**HYPOTHESIS.** Сила игрока зависит от роли; учёт ожидаемой роли уточняет
оценку силы пятёрки.

**DATA.** Позиция 1-5, выведенная из `lane_role`+GPM **прошлых** матчей
(99.6% выводимо). Предсказанная роль — мода прошлых ролей, точность 83.5%.

**LEAKAGE RISK — ВЫСОКИЙ, требует дисциплины.** Роль ТЕКУЩЕГО матча
запрещена (post-match). Используется только распределение по матчам < t.

**EXPECTED SIGNAL — НИЗКИЙ, и это предсказано заранее.** Медиана
стабильности роли 0.927 ⇒ role-conditioned оценка численно почти совпадает с
безусловной, которая уже в модели. Ожидаю эффект, близкий к нулю,
сосредоточенный на ~29% игроков со стабильностью <0.80. **Фиксирую это
ожидание заранее**, чтобы нулевой результат не выглядел задним числом как
«так и планировали».

### F4. Player×Hero×Role

**HYPOTHESIS.** Игрок может быть силён на герое в одной роли и слаб в другой.

**EXPECTED — САМЫЙ НИЗКИЙ приоритет.** По п.5.3 feasibility: роль стабильна,
поэтому разбиение почти не дробит выборку, но и почти не добавляет
информации. Проверяется ради полноты, а не из ожидания успеха.

### F5. Role-uncertainty как отдельный признак

**HYPOTHESIS.** Полезна не сама роль, а **неопределённость** в ней: команда
с игроком на непривычной позиции может играть хуже.

**FORMULA.** `role_entropy(P,t)` — энтропия распределения ролей игрока по
матчам < t; агрегируется по пятёрке.

**ЗАМЕЧАНИЕ.** Это единственная role-гипотеза, которая **не** страдает от
проблемы «роль стабильна ⇒ нет информации» — наоборот, она измеряет ровно
отклонение от стабильности. Ожидание: слабый, но, возможно, ненулевой сигнал.

### F6. Meta-relative player-hero (PART N)

**HYPOTHESIS.** Ценность мастерства игрока на герое зависит от того,
насколько герой силён в текущей мете.

**FORMULA.** Взаимодействие `PlayerHeroStrength × hero_exp_decay_strength`.

**EXPECTED.** Неизвестно. Линейная модель не увидит взаимодействие без явного
произведения, поэтому терм задаётся явно.

## 3. План экспериментов

Все — на **одном** evaluation set. Отбор — **только по VALIDATION**.
TEST — один финальный прогон по заранее зафиксированному списку.

| Эксп. | Состав | Что проверяет |
|---|---|---|
| **E0** | Phase 9 набор | контроль |
| **E1** | E0 + PlayerHeroStrength (лучший half-life по VAL) | F1/F2 — главная гипотеза |
| **E2** | E0 + role-aware player strength | F3 |
| **E3** | E0 + Player×Hero×Role | F4 |
| **E4** | E0 + role entropy | F5 |
| **E5** | E0 + meta-relative player-hero | F6 |
| **E6** | E0 + всё, что прошло VALIDATION | итог |
| **C1** | E0 + Team×Hero | **negative control** (ожидается ухудшение) |

Метрики: Accuracy, ROC-AUC, Log Loss, Brier, калибровка.
Статистика: block bootstrap (блок 20), McNemar, walk-forward по годам.

## 4. Критерий KEEP

Как в Phase 9-10, все условия одновременно: положительный эффект на TEST
при отборе по VAL, CI исключает 0, устойчивость ≥4/5 лет walk-forward,
отсутствие утечки, покрытие ≥80%, интерпретируемый знак коэффициента.

## 5. Заранее зафиксированные ожидания

Чтобы отчёт нельзя было подогнать под результат:

1. **F1 (player×hero) — умеренный положительный эффект**, меньше, чем дал
   roster в Phase 9 (+2.13 pp).
2. **F3/F4 (роль) — эффект около нуля** из-за стабильности ролей 0.927.
3. **C1 (Team×Hero) — ухудшение**, воспроизводя Phase 10.
4. Наиболее вероятный итог фазы: **1-2 признака KEEP, остальные
   REMOVE/RESEARCH FURTHER**.

Если результаты разойдутся с этими ожиданиями — расхождение фиксируется явно.
