## 3. Ответы на финальные вопросы

**1. Лучший источник расписания?**
**bo3.gg** как PRIMARY (378 матчей, 82% известны за сутки), **Valve DPC**
как SECONDARY (официальные `team_id`, но заполнено лишь у 1 лиги из 106).

**2. Лучший источник ростера?**
**bo3.gg** — единственный, кто отдаёт состав до матча. **Liquipedia** —
единственный с интервалами `joindate`/`leavedate`. Оба нужны: первый
отвечает «кто заявлен сейчас», второй — «кто числился на момент T».

**3. Лучший источник ролей?**
**Liquipedia**, `position=1..5`, но только как `PREDICTED_ROLE`.
Источника `CONFIRMED_ROLE` **не существует** среди доступных.

**4. Лучший источник патча?**
**OpenDota** `/constants/patch` — 61 патч с датами релиза. Резерв —
`dotaconstants` на GitHub.

**5. Лучший источник результатов?**
**OpenDota** `/proMatches` — свежайший матч был доступен через несколько
часов после окончания.

**6. Лучший источник драфта?**
Надёжного нет. `/live` OpenDota теоретически даёт, но про-матчей в
выдаче не было (0 из 100). Строить не рекомендуется: Phase 12 показала
нулевой прирост от признаков драфта.

**7. Какие данные реально доступны pre-match?**

| Данные | Доступность |
|---|---|
| факт матча, обе команды, время | **да**, 378 матчей |
| турнир, bo-тип | **да** |
| патч на момент матча | **да** |
| исторический Elo, форма, player-Elo | **да** (собственная база) |
| заявленный состав | **10.1%** матчей |
| роли 1–5 на матч | **нет** |
| драфт | нет |

**8. Насколько заранее?**

| Момент | Матч известен |
|---|---|
| T−7 суток | 30.4% |
| T−3 суток | 57.9% |
| **T−24 ч** | **82.3%** |
| T−1 ч | 98.9% |
| T−15 мин | 100% |

Valve DPC там, где заполнен, даёт медиану **219 ч (9 суток)**.

**9. Как разрешать конфликты?**
Четыре правила по порядку: официальный источник → подтверждение
несколькими → свежесть наблюдения → **явный отказ `UNKNOWN`**. Последнее
правило важнее прочих: неразрешённый конфликт становится видимым и
понижает доверие к данным вплоть до `ABSTAIN`.

**10. Как обеспечить temporal correctness?**
Три метки у каждого факта (`observed_at` / `effective_at` / `event_at`) и
запрос «на момент T», требующий **обоих** условий: факт действовал И был
известен. Проверено на живых данных: состав, прочитанный сегодня, даёт
0 игроков при запросе на вчера.

**11. Можно ли построить production pipeline?**
**Да.** Все восемь шагов цикла (обнаружение → изменения → ростер →
снимок → прогноз → обновление → результат → метрики) обеспечены
источниками без ключа. Конвейер прогноза и разрешения уже построен в
Phase 15 и воспроизводит исторические метрики до третьего знака.

**12. Стоимость MVP?**
**Ноль.** Ни один компонент не требует платного источника или ключа.

**13. Какие ограничения остаются?**
См. раздел 5.

## 5. Ограничения — честно

* **Ростер — слабое звено.** Полный состав есть у 10.1% предстоящих
  матчей; за сутки до старта — у 5.5%. Для большинства матчей прогноз
  придётся строить на историческом составе с пометкой `LOW`.
* **`CONFIRMED_ROLE` не существует.** Ни один источник не заявляет
  позиции на конкретный матч. Для текущего набора признаков это неважно
  (роли в нём не используются), но закрывает целый класс будущих
  исследований.
* **Идентичности источников не сопоставлены.** `team_id` Valve и id
  bo3.gg — разные пространства. Автослияния нет намеренно (Phase 10:
  461 пара одноимённых команд существовала параллельно). Пока
  сопоставления нет, ростер от bo3.gg нельзя приложить к матчу от Valve.
* **Liquipedia непригодна для объёма.** 1 успешный запрос из 3 при
  интервале 3 с. Только с кэшем и никогда как жёсткая зависимость.
* **Valve DPC разрежен.** 38 будущих матчей из **одной** лиги из 106.
  Заполнение сетки зависит от организатора.
* **bo3.gg неофициален.** Стабильность схемы не гарантирована,
  отслеживание изменений не реализовано.
* **STRATZ и PandaScore не проверены содержательно** — только факт 403
  без ключа. Утверждать, что у них есть или нет ролей, оснований нет.
* **Не реализованы** circuit breaker, отслеживание изменений схемы,
  сопоставление идентичностей.

## 6. Что дальше (не предлагается как шаг по умолчанию)

1. **Сопоставление идентичностей** bo3.gg ↔ Valve ↔ собственная база.
   Без него мультиисточник остаётся набором параллельных потоков.
   Делать только с явным уровнем доверия, без fuzzy-слияния.
2. **Замер реальных задержек объявления составов**: наблюдать одни и те
   же матчи в T−24ч, T−6ч, T−1ч и измерить, когда состав появляется.
   Сейчас известна только доля, а не динамика.
3. **Запуск shadow-конвейера Phase 15 на настоящих будущих матчах.**
   Теперь для этого есть источник — впервые за проект.
